Find callers, callees and individual call sites

A caller is a function that invokes another function. A callee is the function being invoked. Studio asks your selected language server for direct call relationships at the captured caret, then lets you inspect the related symbol or each reported call expression.

  1. Open a source document and place the caret on a function or method. Unsaved and read-only drafts can be inspected.
  2. Choose Callers… to find code that invokes this symbol, or Callees… to inspect functions it invokes.
  3. Enter your local language-server executable, its arguments and the project folder. You can load your saved settings for this language. Opening the form or loading settings does not start the server.
  4. Choose Find callers or Find callees. The server receives the captured draft and can inspect the project folder. The request prepares the symbol and retrieves its direct relationships in the same connection.
  5. Choose a relationship in the first list. An arrow shows caller to callee, and the label states how many individual call sites the server reported.
  6. In Symbol or call site to open, choose the related symbol or a specific call site. Read the URI and range in the details first. Changing a choice does not move your editor.
  7. Choose Open selected location. Framework validates the current destination and moves the editor selection. Existing unsaved text and read-only status stay intact.

Understand the locations

The related symbol and its call expression may be in different files. For incoming relationships, the call sites belong to the returned caller. For outgoing relationships, they belong to the prepared root, even when the callee is defined elsewhere. Studio preserves this distinction. Ranges display one-based lines and UTF-16 columns; the end position is excluded.

A relationship with no call-site ranges still offers its related symbol. No range is invented. The summary reports both prepared symbols and relationships, so a symbol with no direct calls can be distinguished from a caret where no symbol was prepared.

If results are unavailable

  1. Check that the selected server supports call hierarchy and UTF-16 positions. Support varies by server and language.
  2. Check its project configuration and indexing requirements. Only the captured draft is synchronized by this action; other unsaved drafts are not sent, and a temporary connection may not have a complete project index.
  3. If source, caret or server settings changed, close the form and capture again. Changing a setting back does not revive an earlier result.
  4. If a returned range is invalid, or a request or server shutdown fails, no partial result is offered. A valid first relationship does not override a failed later response.
  5. For another level of the call graph, navigate to that symbol and start a fresh request. This form does not recursively expand a graph or keep a background index running.

Each inspection accepts at most 16 prepared symbols, 4,096 relationships and 16,384 call sites. Message and parser limits may reject large replies earlier. Navigation never applies or saves text changes and does not add a text edit to Undo.
