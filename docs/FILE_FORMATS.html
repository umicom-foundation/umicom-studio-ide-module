Choose a source file format

A file's encoding describes how characters are represented as bytes on disk. Its line endings separate lines. These choices matter when a compiler, script or another editor expects a particular format. Studio keeps editable text as UTF-8 internally and lets you choose the representation used by the next Save.

Change line endings

  1. Open a disposable source file and select its editor tab.
  2. Open Code tools and enter file format in the filter.
  3. Choose Use LF line endings or Use CRLF line endings. LF uses one line-feed byte; CRLF uses a carriage return followed by a line feed. Follow the convention used by your project.
  4. The command converts all existing endings in the active draft. The selection stays around the corresponding characters. Other source bytes remain unchanged.
  5. Choose Save when ready. Conversion alone changes the draft and its save policy; it does not write the file.

An opened file may already be displayed with LF internally while its save policy still preserves the original CRLF format. Choosing LF in that situation changes the save policy and marks the document modified even if its visible lines look identical. This is intentional: Save will produce different bytes.

Choose an encoding

  1. In Code tools, filter for file format.
  2. Choose the required Use … for Save action from the table below.
  3. Review the modified marker, then choose Save or Save As. An encoding choice does not open a destination dialog by itself.
  4. Open the saved file in the tool that consumes it and confirm that its characters are read correctly.
ChoiceResult on Save
UTF-8UTF-8 without a byte-order mark. Use your project's preferred format.
UTF-8 with BOMUTF-8 preceded by a byte-order mark, a short marker which some tools use to identify the encoding.
UTF-16 LELittle-endian UTF-16 with a byte-order mark. Confirm that the consuming program supports this format.
UTF-16 BEBig-endian UTF-16 with a byte-order mark. The character values are preserved, but their byte order differs from LE.

Changing only encoding preserves the draft's exact text and current line-ending policy. These choices support Unicode characters without substituting a local system code page. They do not reinterpret incorrectly decoded source or add support for arbitrary legacy encodings.

Undo, failures and recovery

Use Undo to restore the previous source, selection and save-format choice; Redo restores the conversion. Earlier unsynchronized typing remains a separate step. Choosing an already active format without changing any text adds no history step. Encoding-only changes still receive their own step.

Undo after a successful Save changes the working copy again. Save once more if you also want the file on disk to return to the earlier representation. Undo never writes to disk automatically. Loading a changed saved file also retains its earlier format in history, including a changed byte-order mark with otherwise identical text.

If a command is refused, keep the draft open. Check that the document is writable and that no save or close workflow is active. Input and converted output must each fit within 8 MiB. Expanding LF to CRLF can exceed that limit. A failed Save keeps the draft and selected format available for another attempt; external-change checks still apply.

Format choices belong to the document in this editing session. Recovery restores source as a new unnamed document; reselect its desired save format before writing it. There is no project-wide default format setting or automatic conversion on typing in this workflow.

Continue with Undo and Redo, draft recovery or editing and saving files.

The encoded file on disk can be larger than its editable text. Open, source navigation, reload and external-change checking allow a bounded serialized size of up to 32 MiB plus three marker bytes, then enforce the existing 8 MiB limit on decoded, normalized UTF-8 text. This accommodates UTF-16 and CRLF expansion without opening oversized drafts partially. The generic document loader still honors the separate byte limit selected by its caller.
