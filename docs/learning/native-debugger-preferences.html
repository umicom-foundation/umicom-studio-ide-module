Choose and save a native debugger

A debug adapter lets Studio inspect a running program. Studio supports a GDB build with DAP support or LLDB's lldb-dap adapter. Choosing an adapter does not install it or start your program.

Use an installed adapter

  1. Open the Debug panel and choose GDB (DAP) or LLDB DAP.
  2. Enter the full executable path, such as C:/msys64/ucrt64/bin/gdb.exe, if that is where you installed a compatible adapter. Leave the field empty to use its usual PATH lookup. Do not add command arguments.
  3. Choose Use adapter. Studio copies this choice into the current window. A running or pending debug session must stop before the adapter can change. Reopening the panel shows the accepted choice.
  4. Review your project's program, arguments and working folder in Project Settings. Build with debug symbols, then use Debug. The existing trust and build-success checks still apply.

Keep the choice for later

  1. Review the two adapter fields and choose Save adapter choice locally. The save runs on a worker and reports its full destination path. A nonempty path must be absolute.
  2. Studio stores native-debug-adapter.json in its per-user configuration folder, using Framework's application-path service. It does not save this preference in the opened project's repository.
  3. In a later window, choose Load saved adapter choice. Loading fills the draft fields; it does not change the active adapter. Review them and choose Use adapter separately.

Open debugger controls without starting an operation

A navigation command changes which controls you can see. An execution command asks a service to act on a process. Keeping these separate makes a debugger usable before a project is trusted and prevents a menu caption from becoming implicit permission to pause an unrelated application.

  1. Choose Run > Attach to Process. Studio reveals Run and Debug and expands the existing Attach to a running application form. It preserves any process ID and symbols-path draft already entered.
  2. Review the selected adapter, project and process identity. Choose an exercise process you started and are authorised to debug. If the workspace is missing, untrusted or busy, resolve that condition before submitting attachment.
  3. Choose Attach to process in the form explicitly. Only this action requests attachment. Operating-system access rules still apply, and a process ID can be reused after a process exits.
  4. Choose Run > Breakpoints to select the existing Breakpoints page in the debugger details notebook. Opening that page does not add, remove, enable or verify a breakpoint.
  5. Inspect requested and adapter-verified breakpoint states separately. A visible row is not evidence that the program will stop at that source location.

Trace the real code path

The Framework menu profile supplies debug.attach and debug.breakpoints. Studio's native router sends them to RuntimeRevealDebuggerControl. This small presentation adapter opens the existing surface, expands the form or selects the current notebook page. It does not call UmiStudioDebuggerAttachNative. The established form callback retains that operation and its workspace authority checks.

The menu commands accept no argument. For example, sending 4321 as a command argument is rejected; it is not treated as permission to attach to that PID. Entering a value in the form is also only a draft until the explicit attachment button is chosen.

Understand the lifetime guard

Changing a native widget can call observers synchronously. An observer might close Studio while an expander is opening or a notebook page is changing. The reveal adapter retains the relevant widget objects, then resolves its weak window binding again before accessing Studio state. A temporary window guard refuses a second reveal command during that transition. Retaining a GTK object does not by itself prove that its application owner is still alive.

Practise and verify

  1. Enter a harmless process-ID draft and an unsubmitted symbols-path draft. Open both menu actions repeatedly. Expect those drafts to remain unchanged, with no build or native debugger session starting.
  2. In an isolated regression fixture, retain a menu button, destroy its workbench, then emit the button signal. Expect no access to the retired owner and no native operation.
  3. Add an observer that closes the workbench when the attachment form expands or the breakpoint page becomes current. The direct command should report cancellation. An observer that tries to reenter the reveal command should be refused while the original reveal completes.

Checkpoint: Why is it reasonable to show attachment settings without workspace trust? The user is inspecting and editing local drafts. Trust and process permission are checked again at the explicit operation boundary. Displaying settings must never silently perform that operation.

Recover from a problem

If loading fails, check the reported location and keep or correct your current draft. A malformed file, unsupported adapter name or relative executable path is rejected. Saving a valid choice explicitly replaces the local settings file. An existing directory or symbolic-link destination is refused.

If you edit the draft while loading, Studio keeps the newer draft. Loading and saving block another preference action or Use adapter until completion. Closing the window discards a loaded result; an explicit save may finish after closing. Save and load never grant trust or execute the selected adapter.

Preferences record a path, not proof of a working installation. An executable can be moved, lack DAP support or require a different environment. Check the Debug output when a launch fails. File replacement does not coordinate competing Studio windows; the last successful save wins.

Extend the workflow

Framework owns validation, JSON, user paths and local file replacement. Studio owns the visible draft and resolves its window again after asynchronous completion. New adapter types should add explicit validation and protocol support before their names are accepted. Keep load, review and execution as separate actions.
