Admit settings and recover AI sessions

A native application receives settings as C values, but that does not make every value usable. A fixed character array may have no terminator. A floating-point value may be NaN, meaning “not a number.” A saved conversation may describe a valid record that would overwrite a newer live edit. This lesson follows Studio's product boundary and the Framework services behind it.

Prerequisites: C structures, pointers, return statuses and the Framework lesson Load conversations without losing state. The APIs below are native service interfaces for contributors. This work does not add a session file chooser or claim a verified GUI recovery workflow.

1. Validate a complete configuration before composition

UmiStudioAiPlatformConfigValidate is a read-only check. It allocates no platform, opens no file and activates no provider. Studio supplies a field schema to Framework's UmiSnapshotValidateTextFields, which searches only inside each fixed array. The shared validator checks schema bounds before reading fields.

#include "umicom/studio/ai_platform.h"

UmiStatus create_local_ai_platform(UmiStudioAiPlatform **out_platform)
{
    UmiStudioAiPlatformConfig config =
        umi_studio_ai_platform_config_default();
    config.allow_remote = 0;
    config.persist_sessions = 0;
    UmiStatus status = UmiStudioAiPlatformConfigValidate(&config);
    if (status != UMI_STATUS_OK) return status;
    return umi_studio_ai_platform_create_configured(&config, out_platform);
}

The constructor performs the same validation itself. The explicit check is useful for a settings form that wants to reject a draft before constructing anything. Passing admission does not guarantee that later allocation, service initialization or provider registration will succeed. Always inspect the constructor's result.

  1. Start with the supplied defaults rather than an incompletely initialized structure.
  2. Copy values using their destination capacities, ensuring each array contains a terminating zero byte.
  3. Validate the draft before any string search, logging or composition.
  4. Construct the platform only after admission. Keep it alive for every callback or worker completion that might use it.
  5. Destroy the platform when the application has retired those users.

The executable, workspace, preferred runtime ID and knowledge archive path are required. Remote fields may be empty while unconfigured, but still must be terminated. If remote access is allowed and an endpoint is supplied, the existing provider ID, model ID and secret-reference requirements apply. A nonzero flag retains its historical true meaning. Validation checks the existing reference syntax; it does not retrieve a credential, approve a remote request, verify an endpoint or inspect whether a path exists.

2. Refuse nonfinite values explicitly

The fitness threshold must be finite and between zero and one, including both endpoints. The expression value < 0.0 || value > 1.0 does not reject NaN: both comparisons are false. Studio now checks isfinite before applying the range. Positive and negative infinity are also refused.

Other checks retain the existing relationships: output tokens must be fewer than context tokens, knowledge overlap must be smaller than the chunk size, and fixed-capacity patch/query counts must remain within their public limits. Do not replace an invalid value with an arbitrary default silently; identify the setting and let the caller correct it.

3. Keep file parsing in Framework

Studio's UmiStudioAiPlatformImportSession forwards a complete candidate to UmiAiAuthorEngineImportSession. The corresponding UmiStudioAiPlatformLoadSessionBounded composes Framework's bounded regular-file reader and import. Studio adds no file-format parser, revision arithmetic or duplicate persistence policy.

ZeroInsert only when this session identifier is absent.
A captured nonzero revisionReplace only that same existing record at that revision.

A valid saved file can still conflict with the destination. UMI_STATUS_BUSY means the expected record identity no longer matches. Preserve the current view and ask the user to review the live record before choosing another replacement. Automatically reading a fresh revision and retrying would defeat this check.

UmiStatus recover_parsed_session(
    UmiStudioAiPlatform *platform,
    const UmiAiConversationRecord *candidate,
    uint64_t selected_revision,
    UmiAiConversationImportReport *report)
{
    return UmiStudioAiPlatformImportSession(
        platform, candidate, selected_revision, report);
}

On success the report separates the file's historical revision, the new archive-assigned record revision and the service revision after active-session selection. The archive owns a copy of the candidate. On refusal, the live archive, active session and report are unchanged. Import can restore metadata for an unavailable model; it does not download, load or invoke that model.

4. Match a completion to its initiating request

The synchronous file interface can block and requires serialized platform ownership for the entire call. A responsive UI should instead load and parse into worker-owned memory, return to its owner thread, verify the initiating request and workspace identity, and then call the in-memory import function. A stored-record revision alone does not prove that the user is still in the same workspace.

Cancel or retire the request when its window closes. Do not pass a borrowed platform pointer to an unjoined worker. Keep UI lifetime checks at the application boundary and reusable file/admission rules in Framework. These functions do not create threads or synchronize concurrent platform access.

Saved approval flags and classifications remain record metadata. They neither enable remote access nor turn persistence on when the current platform forbids it. They are not proof of fresh consent or authenticity. Recheck policy and the current user's decision before later provider execution or saving.

5. Qualify the native integration

From the Applications repository, use the configured UCRT64 toolchain and stop after a failed command:

cmake --preset windows-ucrt64-all-debug
cmake --build --preset windows-ucrt64-all-debug --target umicom-studio-ai-configuration-admission-test umicom-studio-ai-session-recovery-test
ctest --test-dir build/windows-ucrt64-all-debug -R '^studio[.]ai[.](configuration|session-recovery)[.]' --output-on-failure --no-tests=error

The configuration tests cover all fixed fields, required and optional text, exact terminators, remote configuration combinations, numeric bounds and nonfinite fitness. The recovery tests use the real Framework service and build-local files. They check insertion, replacement, conflicts, malformed files, byte budgets and policy preservation. Registration is not execution evidence.

If the target is missing, reconfigure using matching Studio and Framework sources. An import conflict requires reviewing the live record. A parse error requires inspecting a private copy of the saved file rather than clearing the current session. A capacity error can refer to the file budget, fixed archive size or exhausted revisions; use the operation and its input to distinguish them. Keep conversation text and secret references out of public diagnostic reports.

Retain and recheck a context preview

Studio also exposes UmiStudioAiPlatformPlanContextObserved and UmiStudioAiPlatformCheckContextObservation. These thin calls use Framework's service, context and runtime identities. Keep the same live platform and initiating UI request. A BUSY check means a preview is stale and should be rebuilt and reviewed; an OK check is only an identity match, not permission to send a prompt.

Read Detect stale AI context previews for the ownership model. This API work adds no new layout or model execution. The existing settings and recovery code remains in place.

cmake --build build/windows-ucrt64-all-debug --target umicom-studio-ai-context-preview-test
ctest --test-dir build/windows-ucrt64-all-debug -R '^studio[.]ai[.]context-preview[.]' --output-on-failure --no-tests=error

The native integration cases use a real Studio platform and shared Framework state. They verify stale policy, source and runtime updates, unchanged failed outputs and retained local-only settings. Configuration does not execute these cases.
