Run commands in Umicom Studio

The Terminal panel runs a command while the editor remains available. Each session has its own folder and transcript. The summary shows the selected session and its actual folder.

Choose where to run

  1. Open Terminal from Studio's window controls.
  2. Choose Browse… or enter the full path of an existing folder. Project folder fills the field with the open workspace folder.
  3. Choose Apply folder. The summary should show the selected folder. If the folder is missing, relative, unsupported or in use, the previous folder remains active.
  4. Open and review the workspace, then grant it trust before running commands.

Filling the field does not change the active folder until you apply it. Choosing a folder does not create it, grant trust or move files. A chooser answer is ignored after a session change or a newer edit to the field.

Run and stop

  1. Enter a command supported by the selected terminal profile, such as cmake --version when CMake is on that profile's executable search path.
  2. Choose Run or press Enter. Recent output appears in the originating session while the command runs in the background.
  3. Read the final exit code. Zero usually means success; another value requires checking the program's output.
  4. For a command still working, choose Stop. Wait for the final stopped or completed status before starting another command.

Stop refers to the running command even when another terminal tab is selected. The summary identifies that session. Closing its tab or switching projects is refused until completion is published. Closing Studio requests Stop first; close again after it finishes. Revoking workspace trust also requests cancellation.

Retained output

The preview and transcript keep recent output within fixed limits. Earlier text may be omitted, with truncation reported. This is not a full build-log archive. Unchanged refreshes preserve text selection for copying diagnostics.

Arguments, folder and environment are copied when the command starts. Editing another command or selecting another session cannot change the running request. Stop does not undo changes already made.

Use the right tool for the task

Use Build Settings and Build commands for the project's selected compiler and tools. Terminal profiles use their own environment; project tool settings are not silently applied. Use an external terminal for interactive prompts, full-screen programs or a persistent shell. Running cd inside one command does not change the next command's folder; use Apply folder.

Troubleshooting

  • Run is unavailable: check workspace trust and whether another terminal command is pending.
  • Program not found: check the selected profile's search path or supply an explicit program path using that shell's quoting rules.
  • Folder unchanged: apply the draft and read the summary. Failed selections retain the previous folder.
  • The command expects input: this panel does not provide interactive standard input. Stop it and use an external terminal.
