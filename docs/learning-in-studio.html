Choose where you learn and build

The lesson library contains the reading material. Your project folder contains source you edit. Studio keeps these locations separate so a lesson link never depends on the folder that launched Studio.

  1. Open Guided Learning and select Choose lesson library. Select your Umicom-Applications checkout, its Framework folder, or Framework's docs/learning folder. The chosen folder must contain the supplied welcome.html lesson.
  2. Open a lesson. Studio shows its readable local documentation. Reading a lesson does not run code.
  3. Select Create a practice project. Choose your own destination and a C console project. Existing files are not overwritten. Use Open my practice folder to resume an existing project.
  4. Edit src/main.c in Code Editor and save it.
  5. Open Build > Project Settings. Check the CMake program, compiler, source folder and build folder. Grant workspace trust only after reviewing the project; build files can run commands.
  6. Configure the project, then Build. Read Output and Problems if either operation fails. Run starts the configured executable after a successful build.
  7. To debug, configure a supported debug adapter and use a Debug build. Set a breakpoint before starting Debug. To deploy locally, select an installation destination and review the install operation.

If a lesson is missing, choose the library again. A moved or incomplete checkout is not silently replaced with a different folder. The library choice is remembered when session storage is enabled. Project files stay in the destination you select; settings and recovery state remain in private application storage.

Practise with a complete course project

Guided Learning also opens the learning practicum. Select a course, then choose a new project destination using an existing parent folder and a new folder name. Select Use this project destination to prepare the path, and Export this course project to create the files.

Export runs in the background so you can keep reading. Its result belongs to the course and path accepted when you clicked. Once it completes, select Open last exported project in the IDE. Studio receives the actual entry point and build profile; you still review trust, compiler, SDK and debugger settings before executing anything.

The Notes and Assembly stock-total courses are standalone projects. The Framework storage course additionally needs an installed Framework data SDK. Existing folders are never overwritten. If export fails, inspect any partial new folder and select another destination before retrying. Closing the practicum does not undo an accepted export; keep the application running if you want it to finish.

Read portable learning packs

Select Open local learning catalogue in Guided Learning. This opens the Framework catalogue without changing your project. Choose an absolute folder containing learning-pack.json, select Load learning pack, choose a result and select Open selected. Loading runs in the background. Its controls remain unavailable until that request finishes.

Use Search catalogue to match titles, topics and identifiers. The current search accepts up to eight words, with ASCII case-insensitive matching. It searches metadata, not document bodies. The result summary reports when the displayed set is shortened. Back and Forward navigate resources opened within the current pack; opening another pack starts its own reading session.

The catalogue verifies declared bytes before display. Supported HTML presents headings, code, local links and section navigation; unsupported structure uses a labelled plain-text fallback. Inline images retain descriptions. Explicitly opening a declared image resource can show a static PNG when the optional decoder is available. Other images and binary files receive a limitation notice. Reading never runs a source example or grants workspace trust. Each source resource is limited to 1 MiB. PNG illustrations additionally allow at most 2,048 pixels per side and 1,048,576 pixels in total.

The Framework examples/learning_pack_inspector project creates a sample pack during its configuration. Its guide.html explains SDK selection and example commands. Choose its generated pack directory, not the folder containing the learning-pack.json.in template. Studio supplies its compiled Framework version to this catalogue; the manifest's compatibility range must include that version.

Loaded packs and reading history are local to this window and are not saved between sessions. To adopt a newer edition of the same pack, choose its folder, expand Replace a learning pack, and select Review replacement. Check the identity and old/new revision, then select Accept reviewed replacement. Discard replacement abandons only the pending candidate. The existing reader, its links and its examples retain their old revision until you explicitly open a new catalogue result. A changed shelf requires another review. If verification fails, Reload and verify preserves the previous verified reading selection instead of silently accepting different bytes.

Closing Studio closes its catalogue windows. An accepted file read finishes privately and its late result is discarded. A slow or unavailable mounted filesystem can delay orderly application exit until that read returns. The full Framework guide is installed at share/umicom/docs/learning/using-learning-catalogue.html when the Framework learning documentation is included.

Choosing Open local learning catalogue again brings the current catalogue forward with its loaded packs and reading history intact. A different Studio window has a separate catalogue. Closing the catalogue ends that reading session; reopening after closing starts empty. Closing and reopening is therefore an explicit way to load a revised pack with the same identifier.

To inspect a guide's declared example first, select Read linked example. This reads its verified source without copying or running it. Back returns to the guide. Open local link also accepts another declared filename relative to the current guide's folder, such as example.c. Web addresses and paths outside the pack are refused. An optional fragment is remembered in history. Structured guides scroll to an admitted section identifier; plain-text fallback cannot provide structured anchors.

Copy a learning example into your practice folder

In the local learning catalogue, open the example and select Preview example details. Choose a new absolute destination filename in an existing folder, then select Copy example to new file. Expand Last example copy to inspect the exact path and result. Studio keeps the reading selection and its history unchanged.

This copies one verified source file. It does not replace an existing file, open a project or run a command. Review the copied source and follow its guide before compiling it. If a write leaves a partial file, inspect that file; the catalogue does not silently delete it. Closing the catalogue does not undo an already accepted copy.

The detailed replacement guide is installed at share/umicom/docs/learning/updating-learning-packs.html. Keep older pack folders available while reading their editions; acceptance does not copy or overwrite their source files.

Keep private learning checkpoints

In the local learning catalogue, open a lesson or guide and expand Private learning checkpoints. Choose an absolute database filename outside course folders and public repositories, then enter a local learner ID and checkpoint. Inspect checkpoint reads an existing database without creating it. Record checkpoint also needs a short evidence reference and may create the chosen database. Opening a lesson alone never records progress.

Check the captured result after the background operation finishes. It identifies the exact lesson revision, content hash, database and learner. An identical event is not added twice. A storage uncertainty blocks further records until you inspect the same database and learner. Accepted writes may finish after closing; inspect saved records before retrying. These are plaintext private self-recorded actions, not grades or authenticated completion.

The complete walkthrough is installed at share/umicom/docs/learning/record-private-checkpoints.html. The controls require the learning-progress service and SQLite storage; a missing backend is reported without a temporary fallback.

Remember library folders

In the local learning catalogue, expand Remembered learning libraries. Remember the displayed library, then save its folder choices to a new private file. Loading a saved list does not open its folders: choose Reopen selected library explicitly. Changed identities or revisions require review. Existing reading history is kept, and examples never run automatically. The Framework guide docs/learning/remember-learning-libraries.html explains the workflow and refusal cases.

Read this guide through Help

When the native catalogue is included, Guided Learning offers Read Studio learning guide. Studio installs a separate local guide pack under share/umicom-studio/learning-pack inside your installation directory. This pack contains this public guide and a manifest describing its identity, supported Framework version and content hash.

  1. Open Guided Learning and choose Read Studio learning guide. The shared catalogue opens. If the pack is not loaded yet, its notice explains that the matching local pack is missing.
  2. Enter the full path to the installed pack folder and use the catalogue's load action. For an installation at C:\umicom\installed\applications, the folder is C:\umicom\installed\applications\share\umicom-studio\learning-pack. For a source build, the Studio CMake build directory contains the generated learning-pack folder. Choose the generated folder, not the docs source folder.
  3. Wait for loading to finish, then choose Read Studio learning guide again. The guide should appear. F1 while focus is inside this catalogue uses the same guide identity.
  4. Browse another resource or adjust the reading text size. Help returns to this guide through the shared verified reader; it does not change the active project or run a build.

The guide's pack ID is studio.learning-guide and its resource ID is learning-in-studio. They are stable program identities, not search titles. A different locale or missing resource produces a clear refusal instead of an unrelated fallback. This F1 binding applies to the catalogue opened by Studio; it does not replace every editor or debugger shortcut.

If the installed guide has been edited after packaging, reinstall or regenerate the matching pack before retrying. Do not change its digest merely to silence a verification error. Closing Studio retires its catalogue; a retained button cannot reopen a disposed Studio workbench.

View a learning illustration

  1. Load a pack whose manifest declares the PNG as an image resource. A file merely placed beside a guide is not admitted automatically.
  2. Select the image in the search results and choose Open selected, or use an explicit local image link from the guide.
  3. Wait for verification and decoding. A supported image appears in a bounded viewing area, with its resource title as an accessible description.
  4. Use Back to return to the guide. A failed verification on reload keeps the previously verified reading selection.

The Framework guide docs/learning/view-learning-illustrations.html explains authoring and troubleshooting. Animated images, SVG, JPEG and inline HTML pixel placement are not provided by this initial reader. The optional decoder does not establish that a package is from a trusted publisher.

Read the editing, build-error and testing guides

Guided Learning also provides Read the editing and saving guide, Read the compiler error guide and Read the testing guide. These buttons reuse the current local catalogue and the same Studio guide pack.

  1. Load the installed or generated studio.learning-guide pack as described above.
  2. Choose the relevant guide button. Reading begins in the background; wait for its result before requesting another guide.
  3. Use Back to return to a previously opened guide. The catalogue's F1 action still opens the Studio learning guide; choosing another topic does not replace that shortcut.
  4. Follow the guide's instructions in a separate practice project when you are ready. Merely opening the guide does not select a project, grant trust, save a file, compile or run a test.

This pack deliberately contains a small set of public guides. A link to another guide that is not declared in the pack is refused. You can read the wider documentation from its source checkout or a separately reviewed pack; the catalogue does not silently broaden the selected pack's file permissions.

Find text inside a guide

After a structured guide opens, press Ctrl+F inside the catalogue or expand Find in this guide. Enter a word or phrase and press Enter. Use Find next and Find previous to move through matches; the result message identifies a wrap through the guide. This searches the displayed guide, while the catalogue search above it searches titles and topics.

Queries are literal UTF-8 text, up to 255 bytes. Case-insensitive matching applies only to ASCII letters. Find does not modify the open project, execute examples or add reading history. Source examples and plain-text fallbacks are not searchable in this view; return to a structured guide. The editor's document search remains a separate workflow.
