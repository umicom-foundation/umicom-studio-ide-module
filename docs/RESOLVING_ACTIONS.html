Request missing edits for code actions

Some language servers return a quick-fix or refactoring title before calculating its edits. Resolving an action asks that same server to supply the missing edit. It prepares a proposal for review; it does not change your source.

  1. Open a writable source document and place the caret or select the relevant range. Choose Actions….
  2. Select your local language server and project folder. Choose the requested action family to keep the result focused, such as Quick fixes or Refactoring.
  3. If the action may affect other open source files, enable the existing open-draft option before the request. All captured files must use the same language. Closed files are not loaded automatically.
  4. Select Resolve missing text edits. It is off by default. This option requires the server to support action resolution.
  5. Choose Request code actions. Framework captures the selected source scope, obtains diagnostics if requested, lists matching actions and asks for their missing edits before closing the connection.
  6. Choose a supported result and Preview selected action. Inspect the complete proposed changes and any explanations requiring confirmation.
  7. Approve only the changes you have reviewed, then apply through the normal source review. Save separately when ready.

What is resolved

Studio requests missing edits for up to 32 enabled actions in the chosen family. Actions already carrying an edit remain unchanged. Disabled actions and actions requiring commands remain unavailable for application. The server receives each complete original action, including its opaque data, only within the connection that produced it.

Resolving does not grant permission to run commands, create or rename files, or apply an incomplete subset of a proposal. The existing single-document and complete workspace-review rules remain in force. Read-only targets and stale captured source are refused when applying.

Recover from an unavailable result

  1. If the server lacks resolution support, turn the option off and request again to inspect immediately available edits. Studio does not silently change the requested behavior.
  2. If too many actions need resolution, choose a narrower family or source range. The whole request is rejected before resolving any action beyond the allowed count.
  3. If the server changes an action's title, kind, data or other preserved fields instead of adding its edit, Framework rejects the complete publication. Try another server or report the provider behavior.
  4. If an action fails or the common request deadline expires, no partially resolved list becomes applicable. Request again rather than using earlier rows.
  5. Changing source, server settings, source scope or the resolution option retires previous results. Changing an option back does not restore its earlier approval.

All query reads share the existing five-second budget, followed by bounded cleanup. Process launch and synchronous writes are not interrupted by cancellation. Larger or slower projects may require further language-session support.
