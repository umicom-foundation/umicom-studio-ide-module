Editing and saving files in Umicom Studio

This guide uses a small Umicom Notes project to practise the tasks you will use most often in an IDE: opening a source file, changing code, finding a name, saving your work and checking a build.

An IDE, or integrated development environment, brings an editor, build tools and other development tools into one application. The editor changes source text. A compiler checks and translates that source into a program. Saving and compiling are separate operations: code visible in an editor is not necessarily the version currently stored on disk.

Start with a file or a project

  1. Choose New File on the welcome page for an empty source document, or Open File to select an existing local text file. A project is not required for editing and saving.
  2. The source editor is brought into view, including when a saved layout hid it. Type a short comment and check the modified marker on its tab. Selecting another source tab returns typing focus to that document.
  3. Choose Save. An unnamed document asks for a destination; choose a folder you can find in your file manager. A named document saves to its existing path.
  4. To compile a project, choose Open Project Folder and select the directory containing its CMakeLists.txt. Opening a file alone does not select that file's parent as a build project.

Quick Open, Explorer and source navigation from Problems use the same editor. Reopening a path that already has an unsaved draft selects that draft; it does not replace it with the saved file. A failed open should leave existing documents available. Read the notification before retrying.

If the welcome page remains visible after a successful open, or typing does not change the source, record the file path, selected layout and notification. Keep the original file and unsaved text. These symptoms are not a reason to reset the layout database or discard a draft.

Before you begin

Use a disposable practice project, not a production application. You need a built copy of Studio and its supported C toolchain. On Windows, the suite's development build uses MSYS2 UCRT64. On Linux, use the toolchain selected in your build profile. The application build guide explains how to build and start Studio.

Studio's complete-draft path supports up to 8 MiB (8,388,608 bytes) of UTF-8 text per document. A byte is a unit of storage, not necessarily one displayed character; some characters occupy several bytes. The editor should either open the complete supported file or report a limit. Do not remove source code just to make a file fit. Close unused tabs when the overall draft budget is exhausted.

1. Open a project and its source file

For a new practice project, choose File → New Project, select the C23 Console Application template and give the project a new folder. Use a name such as Umicom Notes, a target such as umicom_notes and an application identifier such as org.umicom.notes. Do not create the project over a folder containing other work.

For an existing practice project, choose Open Workspace Folder and select the folder containing its CMakeLists.txt. Open src/main.c using File → Open or the Project Explorer.

A tab represents an open document. Opening the same normalised path again returns to its existing tab and keeps any unsaved text. It does not reload the file from disk. This applies to ordinary path spelling differences such as ./; it is not a promise to recognise every symbolic-link or hard-link alias.

2. Write a small Notes status program

In your practice project's src/main.c, enter this program:

#include <stdio.h>

int main(void)
{
    const unsigned noteCount = 3U;
    printf("Umicom Notes: %u saved notes\n", noteCount);
    return 0;
}

main is where this program begins. noteCount holds an unsigned whole number. const means the program cannot assign another value to that variable after initialisation. The U on 3U makes the literal unsigned, and %u tells printf to print an unsigned value. \n starts a new line. Returning zero reports normal completion to the operating system.

The program does not yet save or load real notes. It displays a value so that you can practise the complete edit–save–build cycle before adding file handling and a graphical interface.

Change 3U to 5U. Before saving, notice the document's modified state. Studio holds your new text in a working copy: the version you are editing. The file on disk can still contain the earlier text.

3. Save the file

Choose Save. For a document without a filename, choose Save As, select the project folder and give it an appropriate filename. Saving main.c elsewhere will not make that other file part of this project's build automatically.

After a successful save, the modified marker should clear. Save All saves named, changed documents through the same document service. If an edited document has no filename, give it a name before building. Do not interpret a failed Save command as permission to discard the editor text.

If another program changes the file, Studio may report a conflict. That protects the other program's changes from being overwritten silently. Keep your unsaved text, compare the two versions and decide which changes to retain. A different spelling of the same path is not a way to bypass that protection.

A Save As dialog belongs to the document that opened it. It must not save a different tab merely because selection changes while the operation is pending.

4. Find the next or previous occurrence

Enter noteCount in the editor's Find field and click Find. One occurrence should be selected. Click Find again to move to the next occurrence. After the last occurrence, searching continues from the beginning. Previous moves in the opposite direction and wraps at the beginning.

These controls search the visible working copy, including text you have not saved yet. Searching does not write the file or add an Undo entry.

Studio uses a smart ASCII-case rule. A search containing an uppercase ASCII letter is case-sensitive, so noteCount distinguishes the uppercase C. A wholly lowercase search such as notes can also find Notes or NOTES. This is a literal text search, not a regular-expression search or full language-aware Unicode case folding.

If no occurrence is found, the current selection stays where it was. When a narrow window does not show all the editor controls, use the command bar's horizontal scrollbar rather than enlarging the source text or removing panels.

5. Replace one occurrence, then replace all

To try a single replacement, find noteCount and enter savedCount in Replace with. Click Replace. The selected occurrence changes. Another click continues from the end of the replacement rather than repeatedly replacing the same text.

Only changing the declaration leaves the later use of noteCount unchanged, so this is a useful moment to practise Undo. Undo the single replacement before the next exercise.

Now enter the same search and replacement and choose Replace All. Review both versions in the comparison, then choose Apply replacements. Choose Cancel to keep the draft unchanged. After applying, both occurrences should become savedCount:

The question belongs to the named document and captured text. Later typing or saving can invalidate it; request a new review before trying again. Read Review Replace All before changing a document for matching rules, limits and recovery steps.

    const unsigned savedCount = 5U;
    printf("Umicom Notes: %u saved notes\n", savedCount);

Replace All is one undoable replacement operation. Click Undo once to restore the text from immediately before that operation. Redo applies it again. The history also retains earlier synchronised edits; it is not an unlimited history of every native keystroke.

A literal replacement can also change comments and quoted strings. It is not a symbol-aware rename. Review the result before saving. Leaving Replace with empty deletes each matching piece of text. Read-only documents reject replacements. If the complete result would exceed the editor's supported size, the original text and replacement history are kept.

6. Build and run

Save the source, then review Build → Project Settings. Check the source folder, compiler, build directory, target and program to run. A project created from a template supplies initial settings. An imported project may need you to select its executable explicitly.

A build profile is the collection of settings used to configure, compile, test and run a project. Review the folder before granting workspace trust: build files can execute programs on your machine. Trust is a separate decision from restoring previously saved settings.

Choose the Build command. Read Output for the compiler transcript and the reported result. On success, use Run. The practice program should display:

Umicom Notes: 5 saved notes

If a compiler error appears, read the first relevant message, return to the named file and correct the source. For example, temporarily remove the semicolon after 5U, build, read the error and restore the semicolon. A failed build must not be treated as a successful run of the updated source.

When checking a build from a terminal, use the project's own preset, not the preset used to build the whole Umicom suite. A generated Windows project commonly uses:

Set-Location "C:\umicom\projects\umicom-notes"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --preset windows-ucrt64-debug
cmake --build --preset windows-ucrt64-debug --parallel 2

A generated Linux project can be built with explicit source and output folders:

cd "$HOME/umicom/projects/umicom-notes"
cmake -S . -B build/linux-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/linux-debug --parallel 2

Replace the example project path with the folder you actually created. Run each command separately and stop when it fails. Studio and the terminal should be compiling the same saved source.

7. Close a document or the application

Change the source once more without saving, then close the document. Studio should ask before discarding modified work. Choose Cancel to return to it, or Discard and Close only when you intend to lose those unsaved changes.

The discard decision is tied to the original document ID. It is not redirected to another tab. If that document has already closed, no replacement tab is discarded.

Closing the application also checks for unsaved documents and running work, including background builds. Cancel returns to Studio. Close Anyway is an explicit decision to leave that session; save important work and stop active jobs normally first. If Studio cannot read the document state, it keeps the window open rather than assuming everything is saved.

Reopen a closed source file

  1. Close a saved source tab, then choose File → Reopen Closed Document or press Ctrl+Shift+T. You can also search for the command.
  2. Check the returned text. A closed file is loaded from its current saved contents; discarded edits and its old Undo history are not restored. If the path is already open, Studio selects that working copy and keeps its current edits.
  3. If a file has moved or cannot be read, restore it and retry. To skip it, choose File → Forget Last Closed Document, then reopen the next entry. Forget does not delete a file.

The history keeps 16 distinct saved absolute paths during this document session. Untitled documents and relative paths are excluded; closing a path again makes it the newest entry. History ends when its document coordinator is destroyed. Reopen follows normal file-opening limits and does not restore old caret, pin or group settings.

Finish or cancel any pending Paste, Save All or document-close question before using Reopen or Forget. Saving regularly and keeping source in Git remain separate from reopening a tab.

Working with larger source files

The workflow stays the same as a Notes project grows: open, edit, review, save, build and run. Search and replacement use the complete accepted draft, not just the beginning of the file. A change near the end is still an unsaved change.

Use a disposable copy of a larger C source file to practise. First look at its last function. Search for a distinctive name there and confirm that Find reaches the expected line. Make one small change, use Undo and Redo, then Save. Close and reopen the saved file and check its end again. This checks more than whether a tab opens.

Try Save As to a new filename, then continue typing in that document. The document's identity stays the same even though its path changes. Ordinary refreshes and path changes should retain the existing editor buffer rather than resetting its text, caret or native undo history.

Undo history is bounded. The document-level history keeps at most 32 entries and 16 MiB of previous text in each Undo or Redo stack, so fewer steps may remain for larger files. Save important changes regularly and use Git for durable, named milestones. Undo is not a replacement for version control or a backup.

A file that exceeds the supported size is not opened partially. Likewise, a replacement that would make a document too large must leave the original text intact. Treat a failed operation as a reason to review the message, not as permission to discard the working copy.

For a runnable explanation of the complete-text API, see the Framework guide at framework/docs/guides/WORKING_WITH_DOCUMENTS.html and its umicom-notes-document example. It performs real document operations without writing over a project file.

For compiler feedback, continue with Reading and fixing compiler errors.

Practise independently

Create a second source file or note in the practice workspace. Move between the two tabs, change one of them, find a repeated word and use Replace All followed by Undo. Save the named files, close the project and reopen it. Compare the text on disk with the version you intended to keep.

You have completed the exercise when you can explain the difference between an open tab, a working copy, a saved file and a compiled executable—and can identify which one each command changes.

Create a Notes header and use Explorer to add project files, browse filtered pages and distinguish disk creation from an untitled document.

Choose where your files live

Open File starts in the active source file's folder, or in your selected project when there is no named source file. Save As starts with the current file's location; an untitled file uses your selected project. Open Project Folder starts from the currently selected project. You can navigate to a different location in every chooser.

When no file or project supplies a location, the operating-system chooser uses its own default. Studio does not turn its private settings directory into a project or create a source folder automatically. Check the displayed destination before saving your first untitled document.

Ctrl+OChoose an existing file with the native file chooser.
Ctrl+SSave the active document. An untitled document needs a destination.
Ctrl+Shift+SChoose a destination with Save As.
  1. Press Ctrl+N and type a short note. The new document has no disk path yet.
  2. Press Ctrl+Shift+S, choose your project folder, and enter a filename. Check the destination before confirming.
  3. Make another edit and press Ctrl+S. Check that the unsaved marker clears. Reopen the file to confirm the saved text.
  4. Press Ctrl+O to select another file. Cancelling a chooser leaves your drafts unchanged.

These shortcuts use the same document and file-conflict checks as the menu. They do not build a project or grant trust. If saving fails, read the notification and keep the document open while resolving its destination or file conflict. The file shortcuts take precedence inside the Studio window; ordinary text selection and editing remain native editor operations.

Choose the source in a split editor

An editor group is a collection of file tabs. When your layout shows two groups, one source from each group can remain visible.

  1. Open two source files and arrange them in separate editor groups.
  2. Click inside the text you want to work on. The source you enter becomes the active document, even if its tab was already selected in that group.
  3. Choose an Edit command, such as Select All. It applies to that source. Moving from the source to a menu does not select the document in the other group.
  4. Click inside the other source to change the command target. Each group keeps its own text buffer and selection.

A read-only source can still be selected and copied; focusing it does not make it writable. Focus changes do not save files. If a command appears to target another document, confirm which source contains the caret and report the two filenames and the action you selected.

Return to a visited location

Studio's Navigate Back and Forward commands use Framework location history. Use Alt+Left or Alt+Right after Go to Line, opening a source or following a Find in Files result. These actions leave source text and text undo unchanged. Clear Navigation History is available in command search.

History is limited to live documents in the current session. Closed tabs and removed lines can make a destination unavailable. Read the source navigation guide for the workflow, failure recovery and host APIs.

Find text without leaving the keyboard

  1. Open a source file or create a new file, then press Ctrl+F. Studio reveals the editor when necessary and focuses its Find field.
  2. Type the text to locate. Press Enter for the next match or Shift+Enter for the previous match. Search wraps around the active document.
  3. Choose Match case or Whole word when needed. These controls apply to both the keyboard and the Find and Previous buttons. Smart case ignores ASCII case unless your query contains an uppercase ASCII letter.
  4. Press Escape in Find to return to the source editor. Searching preserves your unsaved text and does not write the file.

This searches the complete active draft, including unsaved changes. An empty query does nothing; a query with no match leaves the selection unchanged and displays a message. Use the separate workspace Search panel to find text across project files. If no source is open, open or create a file before using Ctrl+F.

Go to a line

Enter a line number, such as 12, or a line and column, such as 12:5, in the editor’s Line:column field. Press Enter or click Go. A valid location selects the source editor so you can continue typing. Columns count UTF-8 bytes; an invalid or missing line leaves your current position unchanged. Navigation does not save or alter your source text.

Replace one match from the keyboard

  1. Find the text you want to change with Ctrl+F. Check Match case and Whole word before replacing it.
  2. Press Ctrl+H to focus Replace with, then enter the replacement. Press Enter or click Replace.
  3. The selected match changes; when no matching text is selected, the next match changes. A second Enter continues after the first replacement. Leaving the replacement empty deletes the match.
  4. Use Undo to restore the previous draft. Review the result before saving; this is literal text replacement, not a programming-language rename.

Find options are shared by keyboard and button actions. A missing match leaves the draft unchanged. Enter in Replace changes one occurrence only; Replace All still requires its separate review. These actions edit the unsaved working copy and do not write the source file.

Save or close several documents

  1. Choose File > Save All to save the open documents. Each named file keeps its existing destination.
  2. For each untitled document, choose a filename in the native chooser. Its starting folder is the project selected when you began Save All. You can choose another folder. With no project open, the operating system chooses the initial folder.
  3. Wait for the completion message and check the saved count. “Save All started” means work has been queued; it does not mean every file has been written.
  4. To stop the remaining saves, choose File > Cancel Save All. Files already saved remain saved; unsaved drafts remain open.
  5. Use Close All or Close Others to review document closure. Answer each unsaved-document question. Cancelling keeps the remaining documents open.

A destination is chosen by you; Save All does not create a project folder or infer one from Studio's settings storage. If a save stops, read the summary, keep the remaining drafts open, and resolve the reported destination or file conflict before retrying.

Cancel a window close

When the window asks about unsaved work, choose Cancel to return to the same drafts. Choose Close Anyway only after deciding to discard unsaved edits. A dismissed confirmation no longer has authority to close Studio. Pending test discovery or execution may first need to stop; read the notification and close again after that operation ends.

Return to a source tab

Reopen Closed Document reloads the newest saved file in closed-document history. It does not restore discarded unsaved text. Reopen, Navigate Back and Navigate Forward reveal and focus the destination editor even when the current layout had hidden it.

  1. Open two files and edit the second without saving.
  2. Use Navigate Back to return to the previous source location, then Navigate Forward to return to the second draft. Its unsaved text remains in place.
  3. Close a saved source tab and choose Reopen Closed Document to return to that file.

A file removed from disk cannot be reopened; the failure leaves the other documents intact. History commands do not build, execute or save your source.

Understand what Build saves

  1. Open the intended project and review Build > Project Settings. Check its source and build folders, then enable its build tools only when you intend to run that project's code.
  2. Start Configure, Build, Test, Clean, Install, Package, Rebuild, Deploy, Run, or Debug. Studio checks the project and active operations before saving the open drafts. A rejected project check leaves your drafts and saved files unchanged.
  3. If a document has no filename, use Save As first. Resolve external file conflicts before retrying. A failed Save All may already have saved earlier documents; inspect the remaining dirty tabs.
  4. If the project or settings change while a save is completing, review the active project and start the command again. Studio does not continue that request against the changed settings.

Run Current uses the selected existing executable. It does not save drafts or compile them, so its output can differ from your latest edits. Use Build and Run when you want the saved changes compiled.

Move between open documents and bookmarks

  1. Open several files. Use Next Document or Previous Document to select another open tab.
  2. Place the caret on a useful line and choose Toggle Bookmark. Repeat in another file, then choose Next Bookmark or Previous Bookmark.
  3. The selected source editor is revealed and focused even when you had hidden its pane. Continue typing in the same working copy; navigation does not save or reload the draft.

Bookmarks are kept for the current document session. Navigation skips bookmarks that cannot resolve to an open source location. When no bookmark is available, the active document stays selected. Use source control for durable progress records.

Review a file changed outside Studio

The editor keeps your unsaved draft when another program changes the saved file. Opening the same path again selects the existing tab; it does not silently replace that draft.

  1. Select the source tab. Use Check external changes on the editor toolbar to inspect its saved file. A missing file is reported separately from a changed file.
  2. Choose File > Reload from Disk..., or the editor toolbar's Reload from disk or Compare with saved action. Studio reveals the source editor and opens the shared comparison.
  3. Read both complete texts: the current editor draft and the captured saved file. The message also shows the saved encoding and line endings. Both panes display decoded text with normalised line endings.
  4. Choose Keep Current Draft to cancel. To adopt the disk version, select the approval checkbox and choose Reload Reviewed File. Reload changes only the captured document and does not write to disk.
  5. Use Edit > Undo to restore replaced text while the document remains open. Use Save As before reload when you want to preserve a separate file containing your draft.

If either the draft or the disk file changes after the comparison opens, Apply refuses that outdated comparison. Keep the draft and open a fresh comparison. If the saved file is missing or unreadable, fix access to that file or use Save As; Studio does not treat a read error as empty source text. Untitled documents have no saved file to reload.

Save All, Close and other document review operations wait until this comparison closes. Reload does not merge two versions automatically, and it cannot prevent another program from changing the file again afterward.

Find the right File action

The File menu groups related tasks: opening a project or document, saving, closing, delivery and exiting. Separators mark these groups. The menu scrolls if your screen cannot display all the actions. A shortcut beside an action describes the same keyboard binding used by Studio.

  1. Choose File > New File (Ctrl+N) to create an editable draft, or File > Open... (Ctrl+O) to choose an existing file.
  2. Type a short line. Choose File > Save As... (Ctrl+Shift+S), choose a folder and filename, then confirm. Continue editing the document at that chosen path.
  3. For a document with a path, choose File > Save (Ctrl+S) to write the current draft. If a save fails, keep the editor open and read the result before trying another location.
  4. Choose Save Copy... when you want a separate new file while the current document keeps its path and dirty state. Save Copy refuses an existing destination. It is a different operation from Save As.
  5. Choose Close Editor when finished. Review the unsaved-work prompt before discarding a draft.

Save As is unavailable until a source document is active. If it remains unavailable, select the source tab and finish any open document dialog. File operations do not compile or run a program; use the project's Build and Run commands after checking its settings and trust.
