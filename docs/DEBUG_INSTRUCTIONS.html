Read machine instructions in Studio

Use the Debug workspace to inspect the instructions associated with a paused function call. This is useful when following assembly, checking compiler output or investigating code without source files. Instruction browsing requires a connected debug adapter that supports disassembly.

Open a page

  1. Open your project folder and trust it only if you intend to run its development tools.
  2. Configure the native debugger, launch or attach to your program, and pause at a breakpoint or with Pause.
  3. Open the Debug workspace. Select the stack frame you want to inspect and expand Machine instructions.
  4. Choose Refresh instructions. Studio captures that frame and asks for 32 instructions starting at its instruction reference.
  5. Read the address, instruction bytes, instruction text and any available symbol or source information. [unavailable] marks a position the adapter could not decode.

Move through the instructions

  1. Choose Later instructions or Earlier instructions to move by the selected page size.
  2. For a precise request, enter a decimal byte offset and instruction offset, select 1 to 64 instructions per page, then choose Read page. A negative offset requests positions before the captured reference.
  3. Turn Resolve symbols on to ask the adapter for names it knows. Symbol availability depends on the program and debugger.
  4. After continuing, restarting, changing projects or selecting another frame, choose Refresh instructions again. Refresh resets both offsets to zero.

Changing a request field clears the old rows immediately. Earlier and Later move relative to the captured reference, without guessing instruction byte sizes. The view displays text; it does not execute instructions, write memory, follow source paths or create breakpoints.

If no instructions appear

  • Adapter does not advertise disassembly: source-level debugging can still work; use an adapter with disassembly support for this view.
  • No instruction reference: refresh the paused stack or choose another frame. Some frames have no machine-code location.
  • Busy or changed state: allow pending debugger events to update, then refresh explicitly.
  • Permission denied: check that the intended project is still open and trusted.
  • Timeout, rejected request or malformed response: inspect the adapter's diagnostic output. A failed request clears the displayed page; it does not resume the program.

Source-level launch and attach configuration are described in the existing debugger guides. Instruction pages share the same connection and project lifetime.

Continue, step and pause

Continuing or stepping retires the previous frame, scope and variable captures before the request is sent. A lost reply cannot make old instruction references current again. Wait for a fresh stop, select its frame and refresh the instruction view. If a control request fails and no new stop arrives, end the debugging session and reconnect before inspecting again.

A Pause acknowledgement means the adapter accepted the request; Studio waits for the stop event before offering paused inspection. Retained text describes an earlier capture until you refresh it.
