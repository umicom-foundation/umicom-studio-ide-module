Recover a local source draft

Recovery keeps an independent local copy of an open document. It is useful before a risky edit or when you want a saved checkpoint of work that has not been written to its source file. A recovery snapshot is separate from Save and Undo.

Keep a snapshot

  1. Open the document you want to protect. The active tab determines which draft is captured.
  2. Choose Recovery… beside Save.
  3. Choose Save snapshot of active draft. Framework copies the complete visible source, including typing that has not reached the document store yet.
  4. Wait for the saved message. The location is shown in the form. Later edits need another snapshot.

Opening the form does not read or write storage. Snapshots start with explicit capture. You can separately enable periodic recovery for the current editing session using the control described below. Capturing does not mark the source as saved or change its Undo history. Read-only documents can also be captured.

Preview and restore

  1. Open Recovery and choose Refresh stored snapshots. Each row shows its modification time in UTC, size and a short identifying key.
  2. Select a row, then choose Preview selected snapshot. Check the complete source and original location shown below it.
  3. Choose Restore preview as new unsaved tab. The recovered text and selected range open in a separate working copy. Existing tabs and files remain intact.
  4. Review the recovered source, then use Save As to choose its destination. If that destination already exists, review the ordinary save conflict rather than assuming recovery permits an overwrite.

A restored document has no artificial Undo entry that could erase the recovered text. Its original path is descriptive metadata; restoration never writes that path. Snapshots remain on disk after restoration, saving or closing. To retire old snapshots, first verify the saved source, close the recovery form, and archive or remove selected .draft files through your file manager.

Protect changed drafts while editing

  1. Open Recovery and read the local-storage notice.
  2. Choose Enable automatic snapshots (every minute).
  3. Close the Recovery form and continue editing. Framework observes the open dirty documents and captures due changed drafts one at a time. Unchanged source and caret movement alone do not create more snapshots.
  4. Reopen Recovery to inspect the number of completed captures or choose Pause automatic snapshots.

The timer belongs to this editing session. It is off again after Studio restarts or the document binding is replaced. Closing the Recovery form leaves an enabled timer running. Source review, saving and closing workflows temporarily defer periodic capture; each document waits at least a minute between completed captures. A large set of documents is handled in rotation, so the interval is a minimum, not a deadline guarantee.

A snapshot is counted only after its write and close succeed. If you type while an earlier snapshot is being saved, the newer source remains eligible for a later capture. A storage or capture error pauses automatic recovery and Studio shows a notification. Keep your drafts open, use Save As if necessary, inspect Recovery, resolve the problem, then choose Resume automatic snapshots.

Automatic admission stops at 256 matching records or 128 MiB of matching record files. It does not delete earlier snapshots. Archive old records outside the recovery directory before resuming. This is an application admission check, not a filesystem quota shared between concurrent Studio instances. Manual snapshots use exclusive creation and may also reach the catalogue limits.

Where source is stored

Studio uses Framework's per-user application recovery directory. On Windows this is under the current user's local application data; on Linux it uses the configured user state directory. The exact resolved directory is displayed, so launching Studio from a different folder does not change where recovery looks.

Snapshots contain plaintext source and original path metadata. They are local files protected by your operating system account and directory permissions, not an encrypted vault. Recovery makes no network request. Keep recovery storage outside projects you publish and use disk encryption when your source needs it.

Limits and troubleshooting

Each snapshot contains at most 8 MiB of UTF-8 text. The catalogue accepts up to 256 matching snapshots and scans at most 4096 directory entries. If it reaches a limit, it reports an error without presenting an incomplete list. Archive older snapshots outside the recovery directory before refreshing again.

Malformed, truncated, oversized or linked files cannot be restored. A write interrupted by an I/O failure can leave a partial snapshot for diagnosis. An unavailable row is not proof of a valid draft: Preview validates the whole record. A missing directory means no snapshots have been stored yet.

If saving fails, keep the document open and use Save As to a writable location. If a preview changes or its selection becomes stale while loading, preview the intended row again. Closing the form cancels work that has not started writing; a write already begun may finish its captured snapshot. Neither outcome changes the original source file.

The older recovery records used by earlier document services remain intact, but this catalogue reads the new complete-draft records only. It does not import those legacy records automatically. See Undo and Redo for the separate in-memory editing history.
