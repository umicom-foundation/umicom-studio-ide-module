Request quick fixes, refactoring and import organization

Use Resolve missing text edits to prepare deferred actions in their original server session before review.

The Actions form can ask a language server for a particular family of changes. A family narrows the choices shown for your captured source. Each proposed change still needs a complete comparison and your approval.

  1. Open the document and place the caret or select the source to inspect. Open Actions….
  2. Enter or load the local language server executable and arguments. Select the absolute project folder. The selected process receives captured source and can read project files.
  3. Choose Requested action family. The default, All actions, preserves the ordinary unfiltered list.
  4. If the server needs diagnostic context to suggest fixes, select Include fresh diagnostics for fixes. Select Use pull diagnostics for fixes as well if it supports explicit diagnostic requests.
  5. If the proposal may touch other open drafts with the same language ID, select Include other open drafts of the same language. Otherwise, a proposal spanning multiple documents cannot be applied through the single-draft review.
  6. Choose Request code actions. Changing the family alone does not start a server or edit any document.
  7. Select a supported edit-only action and preview its complete result. For a multi-document proposal, review every changed document and required annotation before approving the whole change.
  8. Apply the approved result to the captured drafts. Undo remains available in each changed document; Save is separate.
FamilyWhat it requests
Quick fixesCorrections offered for the source range and supplied diagnostics.
RefactoringStructural changes, such as extracting code, where the selected server supports them.
Organize importsThe server's import-organization actions for this document.
Fix allThe server's available fix-all proposals. This is a request for proposals, not an automatic repair of the project.

When no applicable action appears

  1. Check that the selected server offers the requested family. Studio also filters the reply, so unrelated or unclassified actions do not appear under a specific family.
  2. Try All actions explicitly to inspect the server's full response. No automatic fallback broadens your request.
  3. Use fresh diagnostics if the provider needs diagnostic data. Data from a separate Problems window is not reused across connections.
  4. Disabled actions, required commands and unsupported resource operations cannot be applied through this review. Deferred text edits first need the explicit resolution option. Studio keeps the complete proposal and refuses incomplete subsets.
  5. After editing source or changing the family, request again. Changing the family back does not restore earlier choices or approvals.

A family includes its named subfamilies. For example, refactor.extract belongs to Refactoring, while refactorOther does not. The server still determines which operations it can provide.
