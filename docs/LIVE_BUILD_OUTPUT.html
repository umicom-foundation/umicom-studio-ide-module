Follow a build in Studio

The Output surface shows the current phase as it produces text. A separate Latest completed phase view keeps the existing command summary and completed output. This helps distinguish work still running from a result that is ready to review.

Watch your project build

  1. Open your project and review Project Settings. Confirm its source folder, build folder, target and run program.
  2. Confirm that you trust the project before requesting execution. Reading output does not change project trust.
  3. Choose Configure, Build, Test, Run or another supported action from the Build surface.
  4. Open the Output surface. Leave Follow output enabled to see new output and scroll to its end. The status line identifies the current phase and says when its result is still pending.
  5. To read or select an earlier line, turn Follow output off. Compilation continues. The display tells you when newer output is waiting.
  6. Choose Refresh output to show the newest copy once, or turn Follow output back on to resume updates.
  7. Choose Copy displayed output to copy the visible transcript. While paused, this copies what you are reviewing, not unseen output that arrived later.
  8. After the phase finishes, read its status and the Latest completed phase view. Use the existing build-history review to inspect retained completed results. Use Cancel in the Build surface when you want to stop the job itself.

What the transcript contains

The live view retains at most 65,535 bytes from the current phase. A notice appears if earlier bytes were omitted. The next phase starts its own transcript. This is a bounded view rather than a complete log file, and it merges standard output with standard error. For long jobs, Copy displayed output captures only the current display.

Some tools buffer text before sending it, so an empty live view does not necessarily mean the job is stuck. The view repairs invalid UTF-8 text for display and shows an embedded NUL byte as ␀. It does not behave as an interactive terminal or supply keyboard input to a running program. Completed diagnostics continue to use the existing final-result parser.

Recover from a confusing display

  1. If text seems frozen, inspect Follow output and the phase status. Refresh output resumes inspection without restarting the job.
  2. If the current phase is empty but the completed view contains output, the workflow may just have advanced to the next step.
  3. If the phase failed before emitting text, check its completed command and project paths. Correct the cause before starting another job.
  4. If output is truncated, do not treat the copied display as complete evidence. Keep the completed results and use your external build logging workflow when you need every byte.

Keep a full emitted-output file
