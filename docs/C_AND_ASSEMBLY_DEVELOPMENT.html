Developing a C and Assembly Notes application

Edit native source, follow the C ABI, run tests and produce an installed application and ZIP package.

1. The Notes application2. Prepare a development build3. Follow the C-to-Assembly call4. Use the development commands5. Run, install and package Notes6. Inspect C and Assembly while debugging7. Troubleshoot the stage that failed

1. The Notes application

This lesson develops a small command-line Notes application using C and x86-64 Assembly. The C code reads a note and decides how to count lines. One Assembly function counts newline bytes. The same project has tests, an installation rule and a ZIP package, so it can be used to practise a complete native development workflow in Studio.

Open framework/examples/development/c_assembly_notes as the project’s source folder. Read notes.h first, then notes.c, count_byte.S and main.c. The example deliberately exposes a small boundary that can be followed from a C declaration to an instruction sequence.

FileWhat to learn
notes.hA C structure, pointer ownership and the function declaration shared with Assembly.
notes.cInput validation and line-count policy.
count_byte.SThe calling convention, registers, a loop and an Assembly return value.
main.cFile handling, error messages and command-line arguments.
test_notes.cIndependent expected results, invalid arguments and byte-count comparisons.
CMakeLists.txtCompile/link rules, CTest registration, installation and CPack packaging.

The Assembly lesson targets x86-64 Linux or Windows/UCRT64 with GCC or Clang and GNU assembler syntax. It is not an ARM, RISC-V, NASM or MASM source file. A different architecture needs its own Assembly implementation behind the same C declaration.

2. Prepare a development build

Studio is the development interface; the compiler, assembler, linker, CMake, Ninja and debugger are separate tools. Select the intended toolchain rather than relying on whichever installation happens to appear first in the environment.

For the Windows walkthrough, use the following profile values. All paths are examples rooted in the standard Applications checkout. The Run argument is one filename; do not put a shell command in that field.

The Framework profile contract is UmiBuildProfile in umicom/build/profile.h. It includes source/build/install directories, compiler, generator, configuration, target, executable and a single run-argument string. The Notes executable accepts a filename directly, which fits that single-argument form.

The following PowerShell commands also establish the project independently of the IDE. Run them separately. Keep development output outside the source folder.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
$NotesSource = ".\framework\examples\development\c_assembly_notes"
$NotesBuild = ".\build\notes-c-assembly"
cmake -S $NotesSource -B $NotesBuild -G Ninja -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe -DCMAKE_BUILD_TYPE=Debug
cmake --build $NotesBuild --parallel 2
ctest --test-dir $NotesBuild --no-tests=error --output-on-failure

A configure error means the build rules could not be generated. A compiler error points to source that cannot be compiled. A linker error means the compiled pieces could not be joined into an executable. A failed test means a built program did not meet the behaviour checked by that test. Read the failing stage before changing another part of the project.

3. Follow the C-to-Assembly call

/*-----------------------------------------------------------------------------
 * Umicom Framework — C and Assembly example
 * File: examples/development/c_assembly_notes/notes.c
 * PURPOSE: Keep line-count policy in C and call an inspectable assembly leaf.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "notes.h"

int UmiNotesInspect(const unsigned char *text, size_t length, UmiNotesStatistics *out)
{
    if (out == NULL || (text == NULL && length != 0U)) return 0;
    UmiNotesStatistics statistics = {length, 0U};
    statistics.lines = UmiNotesCountByte(text, length, (unsigned char)'\n');
    if (length != 0U && text[length - 1U] != (unsigned char)'\n') ++statistics.lines;
    *out = statistics;
    return 1;
}

UmiNotesInspect rejects a missing output pointer and rejects missing input when the length is nonzero. It fills a local result, calls the Assembly byte counter, then counts a final line that has no terminating newline. Only after the calculation succeeds does it publish the result through out.

size_t is used for memory sizes and counts. An empty note has zero lines. A note ending in a newline does not gain an extra empty line. The reported byte count is not a count of displayed characters: a UTF-8 symbol can occupy more than one byte.

The Assembly implementation is a leaf function: it calls no other functions. Its arguments arrive in registers according to the target’s C calling convention.

TargetText pointerLengthByte valueReturn value
Windows x64RCXRDXR8BRAX
Linux System V AMD64RDIRSIDLRAX

The first instructions normalise those inputs into the registers used by the loop. The loop compares one byte, advances the pointer and decreases the remaining length. A zero length returns immediately, without dereferencing the pointer. No nonvolatile register or stack slot is changed.

/*-----------------------------------------------------------------------------
 * Umicom Framework — C and Assembly example
 * File: examples/development/c_assembly_notes/count_byte.S
 * PURPOSE: Count one byte using the x86-64 C ABI without touching the stack.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
.text
.globl UmiNotesCountByte
#ifndef _WIN32
.type UmiNotesCountByte, @function
#endif
UmiNotesCountByte:
#ifdef _WIN32
    /* Microsoft x64: RCX=text, RDX=length, R8B=value. */
    movq %rcx, %r9
    movq %rdx, %rcx
#else
    /* System V AMD64: RDI=text, RSI=length, DL=value. */
    movq %rdi, %r9
    movq %rsi, %rcx
    movb %dl, %r8b
#endif
    xorl %eax, %eax
    testq %rcx, %rcx
    jz .Lnotes_done
.Lnotes_next:
    cmpb %r8b, (%r9)
    jne .Lnotes_advance
    incq %rax
.Lnotes_advance:
    incq %r9
    decq %rcx
    jnz .Lnotes_next
.Lnotes_done:
    ret
#ifndef _WIN32
.size UmiNotesCountByte, .-UmiNotesCountByte
.section .note.GNU-stack,"",@progbits
#endif

The uppercase .S extension allows preprocessing before assembly. The _WIN32 branch selects the Windows argument registers. The other branch uses the Linux calling convention. Keep these platform differences at the implementation boundary; the C declaration remains the same.

4. Use the development commands

Studio’s build commands operate on the active project profile. Select the Notes project and check the source, build and executable values before running a command. The table identifies the existing commands independently of where a particular workspace places its buttons.

ActionCommand identifierResult to inspect
Configurestudio.build.configureCMake generated the selected build directory.
Compilestudio.build.compileThe application and test targets linked successfully.
Teststudio.build.testCTest executed the registered Notes tests.
Runstudio.build.runNotes printed the byte and line counts for the selected file.

For test-by-test work, use Test Explorer’s Discover, Run Selected, Run All and Stop commands. Background test execution uses the selected item’s recorded build origin. Do not assume that a test from another project belongs to the currently displayed source directory.

Practise a compiler failure by temporarily adding an invalid token to notes.c. Build, read the diagnostic, undo the change, save and build again. Then change an expected value in a disposable copy of test_notes.c to see the difference between compilation success and test failure.

An owned tool operation stops its ordinary helper processes as well as its root process. The existing build runner and verified CTest adapter use this ownership policy. Wait for the operation to reach its final state before starting a replacement build or installing its output.

5. Run, install and package Notes

& ".\build\notes-c-assembly\umicom-notes.exe" ".\framework\examples\development\c_assembly_notes\sample.notes"

$NewNote = Join-Path $env:TEMP ("Umicom-Notes-" + [guid]::NewGuid().ToString() + ".notes")
& ".\build\notes-c-assembly\umicom-notes.exe" --write $NewNote "A note written from a C program."
& ".\build\notes-c-assembly\umicom-notes.exe" --inspect $NewNote

$NotesInstall = Join-Path (Get-Location).Path "build\notes-c-assembly-install"
cmake --install ".\build\notes-c-assembly" --prefix $NotesInstall
& ".\build\notes-c-assembly-install\bin\umicom-notes.exe" $NewNote

cmake --build ".\build\notes-c-assembly" --target package
Get-FileHash -Algorithm SHA256 ".\build\notes-c-assembly\packages\Umicom-Notes.zip"

--write creates a new file and refuses an existing path. The generated temporary name avoids replacing a personal note. --inspect, or a filename by itself, reads a note up to the example’s 1-MiB limit. A file that is too large is rejected rather than partially analysed.

The Notes executable uses standard C file functions. Use ASCII file paths for this Windows lesson; UTF-8 text inside the note is supported. Framework’s Unicode process-launch contract is separate from the file-opening implementation inside a child program.

Installation copies the selected runtime files to a prefix. Packaging collects those installed files into an archive. CPack writes packages/Umicom-Notes.zip and a SHA-256 checksum. This sample ZIP is separate from the Umicom Applications NSIS installer.

6. Inspect C and Assembly while debugging

Build in Debug configuration so source and symbol information are available. Useful breakpoint locations are UmiNotesInspect, where the C policy begins, and UmiNotesCountByte, where control enters the Assembly leaf.

Studio has commands for starting, pausing, continuing and stepping a debug session, including studio.debug.start, studio.debug.pause, studio.debug.step-in and studio.debug.stop. Select the native debugger and the Notes launch profile before starting. A missing debugger executable is a toolchain configuration problem, not a compiler failure.

The same function-level exercise can be performed in GDB. With GDB installed, start it from the Applications directory:

& "C:\msys64\ucrt64\bin\gdb.exe" --args ".\build\notes-c-assembly\umicom-notes.exe" ".\framework\examples\development\c_assembly_notes\sample.notes"

Enter these commands at GDB’s prompt, not in PowerShell:

break UmiNotesInspect
break UmiNotesCountByte
run
continue
info registers
x/10i $pc
stepi
disassemble UmiNotesCountByte
continue

The first breakpoint exposes the C arguments. Continue to the Assembly function, inspect its registers and step one instruction. The program counter identifies the next instruction. The disassemble command shows the function’s machine-code instructions. Compare the input registers with the calling-convention table, and observe the result in RAX when the function returns.

7. Troubleshoot the stage that failed

SymptomWhat to check
Assembler syntax or architecture errorUse the supplied .S file with GNU syntax on an x86-64 Linux or UCRT64 target. Do not pass it to NASM or MASM unchanged.
Unresolved UmiNotesCountByteConfirm that count_byte.S is in umicom-notes-core and rebuild that target.
Run prints usage instead of statisticsUse the complete sample filename as the single profile Run argument, or use --inspect FILE from a terminal.
An existing note cannot be writtenChoose a new filename. The sample refuses to overwrite an existing note.
Stop requested but the view still shows RunningA request and its terminal result are different moments. Allow the owner to publish completion; read the resulting status rather than assuming Stop was a pass.
A Windows tool cannot start with a Unicode pathVerify the selected executable and the input encoding. The child’s own file APIs and any external launcher must also support that path.
No installed executable or packageCheck that compilation succeeded, that the install prefix is correct and that the relevant install/package command finished successfully.
