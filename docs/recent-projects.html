Manage recent projects

The Welcome page lists projects and folders recorded on this computer. A history entry remembers where a project was opened. It is separate from the project itself: removing the entry does not delete its folder, source files or open editor documents.

Open a recent project

  1. Start Umicom Studio and look for Recent Work on Welcome.
  2. Check the displayed path. Different projects can have the same folder name.
  3. Select an available project to open its folder through Studio’s normal workspace workflow.
  4. If the row says Folder not found, choose Browse for a Workspace to locate the folder, or remove the old history entry.

A recorded path is not permission to execute its build commands. Review project trust and build settings separately before configuring, building or debugging.

Pin a project you return to often

  1. Find the project under Recent Work and check its full path.
  2. Choose Pin project. Studio saves this preference before putting the entry ahead of unpinned history.
  3. The button changes to Unpin project. Choose it when you want normal recent-use ordering again.
  4. If the folder is temporarily unavailable, its history can still be pinned. Pinning does not recreate the folder or enable its Open button.

A pin is a preference, not a file lock, a backup or a grant of trust. It does not open the project, change its files, update its last-opened time or start a build. The list still shows at most five entries; use the project browser when a project is not visible.

Remove an entry

  1. Find the entry and check its full path.
  2. Choose Remove from recent projects below that entry.
  3. Studio saves the updated local history before replacing the visible list. A successful operation shows a message confirming that project files and open documents were kept.
  4. To add the project again, open its folder normally. Removing an entry is not a permanent ban on recording it.

Pinned entries can also be removed explicitly. Pinning affects ordering and automatic trimming; it does not prevent the owner from removing their own history entry.

Refresh the list

Choose Refresh recent projects to show the current in-memory history. This is useful after opening another project while Welcome remained available. Refresh does not fetch a repository, open a project, reload another process’s preferences file or run a build. The list shows up to five workspaces with pinned entries first.

When an operation is refused

SituationWhat to do
The entry changed after the row was displayed.Review the refreshed list and choose the intended entry again. Studio does not silently apply an old selection to a changed entry.
The history change could not be saved.The live entry remains. Check that the local state directory is writable and not blocked by another process. Correct the storage problem, then retry.
The history file was damaged when Studio started.Studio preserves that file and uses an in-memory fallback. Durable history changes are unavailable for that session. Keep the damaged file for diagnosis before restoring a reviewed backup and restarting Studio.
The project folder is missing.History removal still works because it changes metadata, not the project directory. Locate the folder separately if you need to resume work.

Where history belongs

Studio keeps the existing .umicom/studio-recent-items location, resolved against the startup working directory once when its services are created. Later changes to the process’s working directory do not redirect history writes. This metadata can contain local project paths; keep it in local application state, outside public commits.

Run one writer for a particular history file. The saved format does not provide cross-process conflict resolution, and atomic replacement is not a guarantee against power loss. Local file operations can also wait for the operating system or antivirus software; this action is not an asynchronous file manager.
