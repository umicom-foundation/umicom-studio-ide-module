Studio Menu Acceptance Guide

Back to the Studio user guide

These exercises specify expected outcomes; they are not a claim that each feature has passed. A visible entry may precede a complete integration. Record unavailable or incomplete features explicitly.

Prepare an isolated exercise

  1. Create a separate practice folder with two source files, a minimal CMake project, one passing test and one intentional failure.
  2. Record the Studio executable, source revisions, operating system, GTK version, compiler and debugger adapter.
  3. The native menu-binding test checks identifiers, captions and handlers for every menu item. It does not execute every command. Other native cases emit GTK signals; they test dispatch and outcomes but bypass physical pointer delivery.
  4. Use a real mouse or keyboard to open each menu. Click Open File, select a fixture, type in its editor, save, switch tabs and close. Repeat after closing Kanban; a blocked pointer or hidden modal window fails this check even if signal-driven tests pass.
  5. For every row below, activate the visible menu and record Pass, Fail, Unavailable or Not run. Skipped checks are not passes.
  6. Capture screenshots and timestamped logs locally, excluding credentials and private contents from shared reports.
Use disposable local repositories and a local bare remote for Git checks, exercise processes for debugging and disposable install/deploy destinations. Check both visible and persisted results: an inaccessible editor is a failure even if a service returned success.

Components outside menus

  1. Exercise New/Open/Save from toolbar and Welcome, checking the same document result.
  2. Edit three tabs, switch repeatedly, close one, save and reopen the others. Verify exact text and reachable editors.
  3. Open Project board, add an exercise card, close the window, edit source and reopen the board. Repeat with a card editor open. No hidden modal window may block Studio.
  4. Open a local lesson, close its reader and open a different lesson without changing the project or draft.
  5. Exercise Explorer filter, refresh, rows and project switching. Verify each real selected path.
  6. Resize and hide panels, restore layouts and repeat keyboard navigation at different display scales.

Completion evidence

Name the command, prerequisite state, visible and persisted result, and evidence for each case. Real debugger qualification is separate from protocol fixtures. Retain failures and rerun them after a fix.
