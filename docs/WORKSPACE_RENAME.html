Rename across open drafts

Studio can ask a local language server to rename a symbol while supplying other unsaved drafts of the same language. The returned changes open in a complete review window. Nothing is applied until you review all changed documents, confirm any required explanations and approve the complete edit.

  1. Open every document that you expect the rename to change. Put the caret on the symbol in a writable source document. Leave unsaved changes open; their current text will be captured.
  2. Choose Rename… in the editor toolbar. Enter or load the language server's absolute executable path, its arguments and the absolute project folder. Opening the form does not launch the server.
  3. Enter the new symbol name. Select Include other open drafts of the same language. This explicitly sends the complete text of all open drafts with the same language ID to the selected local process, including unsaved drafts. The server may also read the project folder. The option starts unchecked.
  4. Choose Request rename. Wait for the query and connection cleanup. A successful response opens Review complete workspace edit.
  5. Read the full captured and proposed text for each changed document. Use Previous and Next, then Mark this draft reviewed. The details list uses zero-based lines and UTF-16 character positions, as supplied by the language protocol.
  6. Read any numbered explanations and their associated edits. Confirm each explanation that requires a decision. Withdrawing a confirmation also clears final approval.
  7. Select I approve the complete reviewed workspace edit, then Apply complete edit. Every captured dependency is checked again before the complete change is applied. No file is saved automatically.
  8. Inspect the result in the editor. Use Undo separately in each changed document to restore its captured draft. Save the documents separately when you want their new contents written to disk.

If the review cannot proceed

A target outside the captured open drafts refuses the complete proposal. Open the needed files and request again. Different language IDs are not included automatically; a cross-language rename needs a host and server configuration that supports those sources. Closed-file edits and file creation, renaming or deletion are not supported by this action.

Read-only documents may be included as source dependencies, but any proposal that edits one is refused. If a captured source, caret, selection, saved state or permission changes, close the forms and capture again. Changing the server settings, new name or draft-inclusion option invalidates a pending request. Cancellation leaves drafts untouched.

The request supports up to 64 drafts. Every serialized source message, including JSON escaping, must fit the native transport's 65536-byte limit. Large drafts or slow server responses can exceed the temporary connection's size or five-second read budget. This is an explicit request, not a persistent project index.

To keep the original single-draft workflow, leave the additional-drafts option unchecked and follow Rename a symbol in Studio. A single-draft proposal containing other targets remains entirely unapplied.
