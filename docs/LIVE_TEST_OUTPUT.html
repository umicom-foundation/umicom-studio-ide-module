Follow tests as they run

Test Explorer shows a live transcript for the most recently started test invocation. You can read progress before the test finishes, keep a passage still while selecting it, and copy the text that is on screen. The existing completed results and selected-test details remain available.

Use the live panel

  1. Open your trusted project and choose its configured build profile. Discover its tests in Test Explorer. A configured build folder supplies CTest's test catalogue.
  2. Run the desired tests using the existing run controls. Look for Latest test invocation output. The context names the test, repetition attempt and invocation number.
  3. Leave Follow output enabled to show the latest capture. Output may also include CTest's own progress and setup or cleanup fixtures associated with the selection.
  4. Turn off Follow output to select and read a stable passage. The status indicates when newer output is waiting. Refresh output shows that newer copy once while leaving Follow disabled.
  5. Select Copy displayed output to copy exactly the text currently visible. It does not silently substitute newer output that arrived while the display was paused.
  6. Use Stop to request cancellation. Wait for the run summary before starting another run. A cancelled or skipped attempt is never shown as a passed test.
  7. Inspect the completed result and failure details after the run. Live text alone cannot establish success; a report or fixture failure can still make the invocation fail.

What is retained

The panel keeps the latest 65,535 raw bytes for the current invocation. A new test attempt starts a new tail. If earlier bytes are omitted, the status says so. This panel does not save a full log to disk or recover test output after restarting Studio. Completed results remain in the existing result view.

A zero byte appears as ␀, and invalid text encoding is repaired for display. This preserves readable text after binary bytes without changing the captured raw data. Compiler output uses the same Framework controls in the Output surface.

If output does not appear

  1. Check whether a test is queued, running, cancelled or already complete in the Test Explorer summary.
  2. Check Follow output. Pausing only affects the display; the running job still captures output.
  3. Some tests keep their own output buffered until they finish. Use a sensible test timeout and inspect final results before assuming the application has stopped responding.
  4. For an execution or report error, inspect the completed result, configured build folder and CTest installation. Discover again after changing the build profile.

Contributors can read the Framework output ownership guide. Studio only selects the current job and copies its evidence; Framework owns execution, byte retention, synchronisation and native output controls.
