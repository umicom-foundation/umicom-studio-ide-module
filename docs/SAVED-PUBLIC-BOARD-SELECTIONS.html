Remember a contributor-board selection

Studio’s project board uses Framework’s native Kanban window. A board document stores private planning work. A separate private publication plan remembers only the fields you reviewed for the contributor website, together with internal board and card identifiers.

  1. Open your project and its project board. Open or create the board document in your chosen folder.
  2. Expand Review a public website snapshot. Select cards, enter public wording and approved developer names, then include each reviewed card.
  3. Expand Save or reopen a private public-selection plan. Choose a private directory and a .umipublic filename. Save the current selection.
  4. On a later session, open the same board and load that plan for review. Check all fields, approve and adopt them. Loading alone does not change the current selection.
  5. Generate the website separately, inspect it and export the HTML. Only that reviewed HTML is intended for your public hosting folder.

Keep the board archive and plan private. A plan does not grant an account or authenticate a contributor. It preserves public wording rather than replacing it with newer private card text. Archived cards and another board’s identity are refused. Refresh a stale board view before adopting.

The independent project-board window can remain open after Studio closes. Its shared Framework controls retain their own I/O jobs. Closing controls suppresses a late load result; an already-dispatched save may still complete.
