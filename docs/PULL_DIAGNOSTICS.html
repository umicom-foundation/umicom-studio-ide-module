Request source diagnostics explicitly

Use related diagnostic source navigation to inspect the other declarations or locations referenced by a message.

Language servers deliver source problems in different ways. Some send notifications after a document opens. Others provide a diagnostic service that the editor must ask directly. Studio's Problems form offers both choices.

  1. Open the source document to inspect. Current unsaved text and read-only drafts are supported.
  2. Choose Problems…. Enter or load the local language server's absolute executable path and arguments, then choose its absolute project folder.
  3. Select Request diagnostics explicitly (pull) if the server offers explicit document diagnostics. Leave it unchecked to use the notification workflow. Changing this option alone does not start a program.
  4. Choose Capture source diagnostics. Studio sends the complete captured draft to the selected local process. The process can also read project files. It requests a full diagnostic report and closes the temporary connection before displaying the result.
  5. Select a diagnostic to read its full message, code, source label and related locations. These values remain plain text.
  6. Choose the reported range or a related destination in Source location to open, then choose Open reported range. Navigation preserves draft text and does not edit or save it.

Recognize the boundaries

An empty report means the requested report contained no diagnostics. It does not establish a successful compilation, completed project indexing or passing tests. Only the primary captured draft is sent. This form does not keep a background connection or continuously refresh problems.

Changing the delivery mode, server settings, draft, caret or selection retires the result. Changing a setting back does not restore an earlier result. Close and capture again when the source changes.

If the request cannot finish

  1. If explicit diagnostics are unsupported, check the server's documentation. Choose notification mode only if it publishes diagnostics that way; Studio does not silently switch modes.
  2. If the server returns an unchanged report, capture again or inspect its configuration. A fresh Studio connection has no previous report to reuse, so it cannot treat an unchanged response as an empty result.
  3. If a report includes additional document reports, the complete response is refused. This form supports one document report, although individual messages can describe related source locations.
  4. If a query times out, check the server path, project folder and compilation database. The temporary connection has a five-second read budget. Large drafts can exceed the 65536-byte serialized-message limit.
  5. If a coordinate is rejected, capture current source again. Studio checks Unicode boundaries and does not round an invalid position to make the result appear usable.

For proposed corrections, see Actions. It has separate controls for fresh diagnostic context and pull delivery. Its context is captured in the action's own connection; this Problems result is never replayed into another provider session.
