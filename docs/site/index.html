User guide: follow one development cycle

Use a disposable Umicom Notes project for your first session. Prepare the supported toolchain, start Studio, then open the folder containing the project's CMake configuration. Check that you are editing the intended source file, not a copy in another folder.

  1. Create a project through File → New Project, or open an existing workspace folder.
  2. Open a source document. Change it and save; the editor draft and compiled program are different things.
  3. Review the project settings and grant workspace trust only after reviewing its build files.
  4. Build the project. Inspect Output and Problems; a failed build needs correction before Run.
  5. Open a reported problem, fix the source, save and rebuild.
  6. Close and reopen the project. Check its files and settings rather than assuming every piece of session state was restored.

Editing and saving source files and Reading compiler errors give the detailed exercises. Native Windows and Linux interactions need checking against your own build.

Support and contribution

When reporting a problem, include the application revision, operating system, exact action and error output. Remove credentials, private account information and personal file content. Use the repository issue tracker for a reproducible defect and the contributor guide for documentation improvements.

Reload a changed source file

When another editor or Git updates a saved file, use the reload lesson to choose which version to keep and preserve unsaved work.
