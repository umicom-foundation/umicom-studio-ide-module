Navigate and select matching brackets

The toolbar now groups these actions under Code tools or Navigate and view. See finding editor tools for their locations and local filters.

A delimiter marks the boundary of a group of source text. Studio can navigate balanced parentheses (), square brackets [] and braces {} without starting a compiler or language server. These actions complement the bracket highlighting available when the editor uses GtkSourceView.

  1. Open a source document and place the caret at a bracket, or immediately after it.
  2. Choose Matching bracket in the editor toolbar. Studio moves to the other end of that complete pair. If brackets are adjacent, the bracket at the caret takes precedence over the one just before it.
  3. To select a group, place the caret inside it and choose Select inside brackets. The nearest complete enclosing pair supplies the selection; its brackets are excluded.
  4. Choose Select bracket pair to include the two brackets. Selecting inside an empty pair leaves an empty selection between its brackets.
  5. Use the existing navigation Back action to return to the prior location. Source text, its saved state and text Undo are unchanged by these actions.

Language rules

For documents identified as C, the scanner ignores ordinary quoted strings, character literals, line comments and block comments. It accounts for escaped physical newlines and digit separators while preserving the original source positions. For JSON documents, it ignores double-quoted strings. Other languages use literal matching, which counts bracket characters inside comments and strings too.

The C scanner is a lexical aid, not a compiler. It does not expand macros, choose active preprocessor branches, recognize digraphs or interpret C++ raw-string syntax. Angle brackets are not matched because their meaning depends on language syntax. An unfinished quote or comment masks the remaining text in that profile. Crossed pairs such as ([)] are refused; independent complete pairs later in the draft can still be found.

If nothing is selected

  1. For Matching bracket, move directly onto a bracket or just after it. A bracket at the caret that has no matching end does not fall back to an earlier completed pair.
  2. For an enclosing selection, keep the caret between the opening and closing bracket, including either bracket. A caret after the closing bracket is outside that pair.
  3. Check that the document language matches the intended profile. This workflow accepts drafts up to eight MiB and at most 512 simultaneous nested opens. Invalid text or excess nesting is refused without changing the draft.

Read-only drafts permit navigation. A destination inside manually folded code is revealed when the editor displays the new location. For language-aware expressions and declarations, use source assistance and its explicit server selection workflow.

The same actions are available in command search as Matching Bracket, Select Inside Brackets and Select Bracket Pair. They use the current caret and take no filename or other argument.
