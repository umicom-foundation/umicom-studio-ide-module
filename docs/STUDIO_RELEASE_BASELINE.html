Know what “Studio is ready” actually means

A beginner-friendly STU-01 guide for turning existing IDE features into one stable product.

Why this checkpoint exists

Umicom Studio already contains editors, project tools, build services, tests, debugger workspaces, Git tools and a visual designer. A stable release needs something stricter than “the source exists”: each feature needs a visible route through Studio and an acceptance result.

Important: this checkpoint does not mark Studio complete. It makes the release target explicit so later batches close named gaps instead of adding unrelated features.

Try the native catalogue

umicom-studio-release-baseline catalogue
umicom-studio-release-baseline explain STU-08
umicom-studio-release-baseline --self-test

The catalogue is read-only. It starts no compiler, debugger, Git command or graphical application.

The first practical capstone

StepWhat must eventually work in the installed IDE
1Create an Umicom Notes project.
2Edit two files and save only the intended document.
3Introduce a compiler error and navigate from Problems to the exact source location.
4Run an exact selected test and distinguish pass, fail, skip and not-run outcomes.
5Debug a native defect with the selected frame and variables.
6Review a Git change without publishing unrelated files.
7Generate a small GUI with the Framework-owned designer and run it.
8Close and reopen Studio without losing accepted work.

What comes next
