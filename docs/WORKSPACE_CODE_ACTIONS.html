Review code actions across open drafts

Use action families to request quick fixes, refactoring, organize-imports or fix-all proposals while retaining complete review.

Choose how diagnostic context arrives

Some fixes need the server's diagnostic data. Select Include fresh diagnostics for fixes to obtain that data within the action request's own connection. The default waits for a notification. Select Use pull diagnostics for fixes as well when the server offers explicit diagnostic requests.

  1. Choose the source scope and both diagnostic options before requesting actions. The pull option has no effect while diagnostic context is unchecked.
  2. Choose Request code actions. All selected drafts are sent first. Framework requests a complete diagnostic report for the primary draft, validates its ranges and includes the relevant original diagnostic objects in the action context.
  3. Select a returned edit-only action and use the normal complete comparison and approval workflow. Diagnostics themselves do not grant permission to edit.

Missing providers, refused or unchanged reports, invalid ranges and unsupported related-document reports stop the action request. Studio does not replace a failed diagnostic capture with an empty context. Changing either diagnostic option retires pending choices and approvals, even if changed back afterward. Captures shown in a separate Problems window are not reused across server connections.

A code action is a change proposed by a language server, such as a correction or an extraction into a helper function. Studio can supply other open drafts of the same language and review a complete text-only action across those drafts. The server chooses which actions it can offer.

  1. Open the documents that the action may need. In the primary document, place the caret or select the source range you want to work on.
  2. Choose Actions… in the editor toolbar. Enter or load the local language server's absolute executable path and arguments, and choose its absolute project folder.
  3. Select Include other open drafts of the same language. This sends complete current text, including unsaved changes, for every open draft with exactly the same language ID. It can include drafts outside the chosen project folder. The option starts unchecked; the local process may also inspect files itself.
  4. If the server needs diagnostic context, select the separate diagnostic option. A diagnostic is a reported problem with a source range. Framework obtains fresh diagnostics for the primary draft from the same connection before requesting actions. Missing context reports an error instead of silently requesting without it.
  5. Choose Request code actions and wait. Select an available edit-only action in the returned list. Selecting another action changes its description without discarding the captured source dependencies.
  6. Choose Preview complete draft. In this mode the preview opens a separate complete workspace review. Read every changed draft's captured and proposed text, then choose Mark this draft reviewed. Use Previous and Next to move between drafts.
  7. Read the edit details and any numbered explanations. Confirm each explanation that requires a decision. Then select I approve the complete reviewed workspace edit and choose Apply complete edit.
  8. Inspect the changed drafts. Save separately when ready. Undo restores each changed draft separately.

When an action cannot be applied

Studio does not execute a language-server command or apply just the edit portion of an action that also requires a command. Disabled actions show their reason. Actions that require another request to resolve their edits remain unavailable. File creation, file renaming and file deletion are not supported by this review.

Every edit target must be one of the captured open drafts and must be writable. Read-only drafts may supply context, but they cannot be edit targets. Unknown targets, invalid ranges or mismatched protocol versions refuse the complete proposal. No subset is applied.

Changing any captured source, saved state, caret, selection, identity, permission or conflict state requires a new capture. Changing the server settings, diagnostic option or draft-inclusion option retires the current request. If the complete review has taken ownership of an action, request again to choose another action after closing that review.

Current bounds

The capture accepts up to 64 documents. Each serialized source message must fit 65536 bytes, including escaping and the protocol envelope. A temporary connection has a five-second read budget. This explicit action does not create a persistent project index or a background diagnostic subscription.

Leave the additional-drafts option unchecked for the single-draft workflow. The same complete review also supports rename across open drafts.
