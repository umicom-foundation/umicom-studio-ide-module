Registers and Disassembly in Umicom Studio

Follow a C programme into Assembly using Framework-owned debugger data.

Open a practice project

Use the C and Assembly Notes example in framework/examples/development/c_assembly_notes. Configure and build it with Debug symbols, then open the Run and Debug activity.

Pause execution

Add a breakpoint in the C source before the Assembly routine is called. Start debugging, continue to the breakpoint and select the stopped thread and stack frame. Registers and disassembly describe that selected paused frame.

Read the Registers pane

Open Registers from Run and Debug. Choose Refresh. On x86-64, find RIP for the current instruction address, RSP for the stack pointer and the argument registers used by the platform calling convention. A marker beside a register indicates that its value changed since the previous successful refresh.

Read the Disassembly pane

Open Disassembly. The first current row begins at the program counter when the adapter provides a recognised counter register. Each row shows an address, instruction bytes, mnemonic and operands.

> 0x401020  48 83 c0 01  add $0x1, %rax
  0x401024  c3           ret

Compare the instructions with count_byte.S. Source-level lines and machine instructions are not one-to-one, especially in optimised builds.

Refresh after a step

After Step Over, Step Into or another stop, select the intended frame and refresh low-level inspection again. This updates the register snapshot and, when supported by the adapter, obtains instructions from the new program counter.

Variables show language-level values. Registers and disassembly show processor-level state. Use both views together when learning how C calls Assembly or when diagnosing generated machine code.
