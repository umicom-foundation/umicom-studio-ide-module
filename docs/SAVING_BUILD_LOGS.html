Save a complete build log in Studio

Studio can save output to a file while the Output surface follows the running job. The file records all output emitted by the background workflow, including text that no longer fits in the live viewer.

Choose a file for the next job

  1. Open the Output surface. Find Save complete emitted output to a new file.
  2. Enter an absolute filename in an existing folder you control. For example, if you have created C:\umicom-build-logs, enter C:\umicom-build-logs\studio-build.log. Choose a location outside your source checkout when you want logs kept out of commits.
  3. Choose Use log for next job. The status shows the selected path. Typing alone does not select the file, reserve it or start a build.
  4. Review Project Settings and workspace trust, then start a background action from the Build surface. The next accepted background job consumes the selection. This also applies to the build requested before native debugging.
  5. Follow compilation in Output as usual. Pausing Follow output affects only the display; the log continues to record.
  6. When the job ends, check the build result and log status separately. Emitted output saved confirms capture of the bytes received, not that compilation or tests passed.
  7. Use Copy log path to copy the path of the last accepted job's log, then open it with your preferred text or binary viewer. This button does not copy a filename that is still only a draft.

Select a fresh filename before another job if you want another log. Disable next log clears the pending selection. It does not delete existing logs. A busy job refuses changes to the selection.

If a log cannot be saved

  1. If the filename already exists, the job is refused before its commands run. Choose a different name and select it again.
  2. If the parent folder is missing or inaccessible, correct the path or folder permissions. Studio does not create folders here.
  3. If a write, flush or close fails after the job starts, the log status reports incomplete capture. Keep the partial file and inspect the build result separately. Studio does not automatically retry, overwrite, cancel or restart the build.
  4. If you cancel, bytes already emitted are retained and the log is closed. The file cannot recover output that the tool kept in its own buffers or output from phases that never ran.

Output and retention

The log is raw combined standard output and standard error. It contains no inserted phase headings or command summaries. The existing completed-result view and build history provide that context. The live display may repair text for readability; the file preserves the original bytes instead. A log may therefore need a binary viewer.

Logs have no automatic rotation or size limit and remain on disk until you manage them. Storage problems and slow disks can affect writing and job completion. Review logs before sharing them because programs may print private paths or other sensitive values. The selection is session state, not a saved project setting. It applies to background build workflows; older synchronous service calls and unrelated terminals keep their existing behaviour.
