Building and testing a project in Studio

Source files contain instructions written by a developer. A compiler turns them into a program. Tests execute checks against that program or its components. Studio uses Framework services to save project inputs, run the configured tools and retain their outcomes.

Find the editing and project controls

  1. Open File. New Project, New File and Open... appear before the save and close actions. Long menus scroll so their lower actions remain reachable on a smaller screen.
  2. Choose New File for a blank editable document. Opening a source file alone does not create a build project: use Open Folder... to select the folder containing CMakeLists.txt, or create a project.
  3. The default editing layout keeps the project explorer beside the editor. Saved personal layouts keep their own panel placement; changing the default does not overwrite them. Use the workspace's panel controls to show a hidden explorer.
  4. Use Build and Run menus for project operations. The Build panel displays their status and output. A disabled command means a prerequisite is missing; review the project settings and the current operation before retrying.

Prepare a project

  1. Open a project folder containing its build configuration. For a first exercise, create a C23 console project through Studio's project creation controls.
  2. Open Project Settings. Review the source folder, build folder, selected configuration and executable. A build folder holds generated outputs; it is separate from your source files.
  3. Enable workspace trust only for a project whose commands you intend to execute. Merely opening a folder does not authorize its build commands.
  4. Open the Build panel. Its buttons wrap when the panel is narrow; use vertical scrolling if the available height is small.
ActionWhat to expect
ConfigurePrepare the build system from the project configuration.
BuildSave eligible project inputs and request Framework's automatic project qualification. With testing enabled this may also execute tests.
TestSave edited project inputs, build the required test inputs and execute tests through the configured preset or supported automatic driver.
Build and RunSave inputs, configure and build the selected target, then launch the configured program if those stages succeed. This action does not promise a full test run.
Run current executableLaunch the already-built configured program. It neither saves drafts nor rebuilds the program, so it can run an older version of your source.
CancelRequest cancellation of the active operation. Wait for completion before starting another operation.

Repair a failing test

  1. Select Test and wait for completion. Review the reported process status and output.
  2. Read the failing test's source and diagnostic. A compiler error and a failed test are different: a test failure means a check executed and rejected its result.
  3. Correct the relevant source in the editor.
  4. Select Test again. Confirm a new operation ran and the previously failing check passed. An old successful result is not evidence for the edited source.
  5. Review remaining skipped tests separately. A skipped check did not verify its behavior.

When a control cannot start work

Review workspace trust, project settings and the current operation first. Launch-only execution requires an existing executable and a valid working folder. For missing tools, fix the configured compiler, CMake or CTest path. Preserve the output of the failed operation rather than repeatedly changing settings without recording the result.

Native workflow checks

The studio.first_use.gtk4.visible-test-repair scenario edits a real generated test, observes its failure and repairs it through the native editor. studio.first_use.gtk4.visible-run-current confirms that launching an existing program leaves a deliberately invalid unsaved draft and the saved source unchanged. They use real process outcomes, a presented Studio window and its actual Build panel buttons.

These are GTK widget integration tests, not operating-system mouse injection. They retain their isolated generated project and PNG checkpoints in the qualification directory printed by the test. Review those images and manually exercise pointer and keyboard interactions as well. No application usability claim follows from a window opening alone.
