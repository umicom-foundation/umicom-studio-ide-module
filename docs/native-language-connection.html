Check a language server in Studio

A language server is a local program that analyses source code. Studio's Outline panel includes a connection check for servers that communicate through standard input and standard output. It checks the protocol handshake and displays selected capabilities, then closes the server.

Run a connection check

  1. Install the server you want to use. For a C project this might be clangd. Select an executable you trust and a folder you are comfortable letting it inspect.
  2. Open Studio's Outline panel. Find Check language server below the language-service summary. Opening the panel runs nothing.
  3. Enter the full path in Server executable, including the executable filename. A path containing spaces does not need surrounding quotes in this field.
  4. Enter any arguments required by that server. This field accepts quoted argument values and does not expand shell expressions. Leave it empty when the server needs no arguments.
  5. Review Project folder. It starts with the folder that was open when the panel was created. You may edit it before checking.
  6. Select Check language server. The check runs on a worker so the form can remain responsive. Use Cancel check to request cancellation.
  7. Read the result. Success reports a completed handshake, child shutdown and whether the server advertises completion, hover, definitions, references and formatting.

Understand the result

This action does not activate editor completion, configure the existing language-service summary, send document text or save the selected settings. The server is closed after the check. A server can inspect the project directory during its own initialization, and a successful handshake does not prove that every advertised feature works for the current project.

Changing a field during a check invalidates the old result, even if you change it back. Hiding or closing the panel requests cancellation. When you return, run a fresh check for the displayed values. Native startup and synchronous writes cannot always be interrupted immediately; child cleanup may finish after the panel closes.

Resolve a failure

  1. Check that both paths are absolute and point to the intended executable and directory. A missing tool is not installed automatically.
  2. Confirm that the server supports standard-input and standard-output communication. A network-only server needs a different transport.
  3. Review its required arguments and installed dependencies. The server's standard-error diagnostics remain separate from protocol stdout and may be visible in the console used to launch Studio.
  4. For a timeout, check the server's own logs or startup requirements before retrying. The UI reports initialization and shutdown separately so an initialization success cannot hide a cleanup failure.

Framework owns native argument handling, Unicode Windows paths, handshake correlation and cleanup. Studio only embeds the form and supplies an editable project-folder draft.
