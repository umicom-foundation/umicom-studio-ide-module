Restart a debug session

Restart asks the active debugger to run the same program again with the launch settings it already holds. It does not compile changed source or load a different project. To compile your edits, use Stop and then Debug.

Use Restart

  1. Open a project you trust and select its program, arguments and working folder in the build settings.
  2. Choose an installed GDB with DAP support or LLDB DAP, then choose Debug. Wait for the build and debugger startup to finish.
  3. Open Run and Debug and choose Restart. The same command is available from the Run menu and command search as Restart Debugging.
  4. After the debugger reports a new stop, inspect the new thread, stack and variable values. Old captured values are retired when the restart is attempted.
  5. Your watch expressions remain in the list, but their previous results are cleared. Evaluate an expression explicitly when you want its new value; evaluation can execute code in the program.

Understand the result

An accepted restart means that the adapter acknowledged the request. Studio still waits for debugger events before presenting the next stopped location. Breakpoint choices and watch expressions remain yours.

If the adapter does not advertise restart support, Studio leaves the session intact and reports that it is unsupported. Choose Stop and Debug to start again. If a build is pending, wait or cancel it separately. Restart does not cancel the build.

A timeout, refused request or invalid response can leave the program state uncertain. Studio does not restore old variable references or automatically resend the request. Use Stop, inspect any reported error, and choose Debug to create a new session.

For contributors

Studio contributes the command and native controls. Framework checks the adapter capability, owns the protocol request and retires inspection evidence before any possible write. Keep new frontends on this shared path so they apply the same lifetime rules.

The operation follows the Debug Adapter Protocol restart contract. Support depends on the installed adapter. A saved project change is deliberately separate from restarting an existing session.

Adapters that initialize again

Some adapters request another configuration exchange while restarting. Framework sends the saved source breakpoints and, when supported, configuration completion before continuing. The same restart timeout bounds this exchange. An initialization event that arrives after the restart reply is handled by normal debugger polling within that original budget.

If configuration is rejected or times out, use Stop before beginning a new session. The old variable references remain retired, and Studio does not automatically repeat the restart request.

After restart is acknowledged, Studio waits for the adapter to report initialization, continuation or a new stop before allowing another restart. If the adapter stays silent, use Stop and start a fresh debug session. A successful request reply alone does not provide fresh stack frames or variable references.
