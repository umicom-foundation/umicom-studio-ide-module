Umicom Studio IDE: reviewing saved session values

This contributor API transfers a product's layout identity, ordered active panel IDs and lock state. Framework owns encoding, validation and the lifetime of catalogue strings. These are library operations; they do not add an import menu or automatically restore the native interface.

Use the product boundary

  1. Initialize a UmiApplicationSession with the canonical org.umicom.studio experience from Framework's catalogue.
  2. Include umicom/studio/workspace_commands.h. Measure the archive using umi_studio_workspace_session_capture with a null byte buffer and zero capacity, then allocate and encode the measured size.
  3. Remember the live session revision before starting a review. Use umi_studio_workspace_session_preview to inspect a candidate without changing the live session.
  4. Show the candidate layout and panel identities to the user. Prepare any native presentation separately; the candidate contains no widgets or running services.
  5. After confirmation, call umi_studio_workspace_session_apply with the observed revision. Success advances the current local revision once. A stale observation leaves the session unchanged and requires another review.
  6. Free the caller-owned byte buffer. The resulting session keeps catalogue-owned panel identifiers, so it does not depend on that buffer's lifetime.

Keep live resources under their owners

These calls do not save documents, launch programs, reconnect brokers, place orders or grant permissions. Use the existing workspace checkpoint services for native placement persistence and each live service's recovery API for its own resources. Continue checking product capabilities before activating a panel.

Respond to a refused import

  1. Keep the active session available. Failed decoding, preview and application leave their destination unchanged.
  2. For a damaged archive, preserve the original bytes and obtain another saved copy.
  3. For an unknown panel or layout, choose a supported replacement through the product's normal workflow.
  4. For UMI_STATUS_INVALID_STATE, capture the latest revision and repeat review. Do not retry using the counter stored inside the archive.
  5. Serialize access on the owner thread. A revision comparison is not a replacement for synchronization.

A locked session refuses application with UMI_STATUS_PERMISSION_DENIED. Unlock through the Framework session API and review again using the new revision.
