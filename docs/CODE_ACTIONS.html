Code actions in Studio

Use Resolve missing text edits to prepare deferred actions in their original server session before review.

Use action families to request quick fixes, refactoring, organize-imports or fix-all proposals while retaining complete review.

Choose how diagnostic context arrives

Some fixes need the server's diagnostic data. Select Include fresh diagnostics for fixes to obtain that data within the action request's own connection. The default waits for a notification. Select Use pull diagnostics for fixes as well when the server offers explicit diagnostic requests.

  1. Choose the source scope and both diagnostic options before requesting actions. The pull option has no effect while diagnostic context is unchecked.
  2. Choose Request code actions. All selected drafts are sent first. Framework requests a complete diagnostic report for the primary draft, validates its ranges and includes the relevant original diagnostic objects in the action context.
  3. Select a returned edit-only action and use the normal complete comparison and approval workflow. Diagnostics themselves do not grant permission to edit.

Missing providers, refused or unchanged reports, invalid ranges and unsupported related-document reports stop the action request. Studio does not replace a failed diagnostic capture with an empty context. Changing either diagnostic option retires pending choices and approvals, even if changed back afterward. Captures shown in a separate Problems window are not reused across server connections.

This guide describes the single-draft mode. See review code actions across open drafts for explicit additional-source scope and complete workspace application.

Ask a local language server for fixes and refactors at the caret or selected range. Studio shows complete proposals and requires review before changing a draft.

  1. Open a writable source document and place the caret or select the relevant expression or statements. Selections can span lines.
  2. Choose Actions… in the editor toolbar.
  3. Enter the installed language server's absolute executable path, its arguments and the absolute project folder. You can load saved settings for this language. No program starts until you request actions.
  4. Choose Request code actions. The chosen local program receives the captured draft and range and may inspect the project folder.
  5. Select a choice and read its availability. Preferred means the server recommends that choice; it does not grant approval. Disabled choices show a reason. Commands remain unavailable. Deferred text actions can be prepared by explicitly selecting Resolve missing text edits before requesting actions.
  6. Choose Preview selected action for a supported text edit. Compare the entire source result and read all numbered explanations, including confirmation requests.
  7. Approve the displayed action and confirmations, then choose Apply to captured draft. One Undo restores the captured source. Save separately when ready.

Changing the selection in the action list clears approval. Changing server settings clears the choices. If the source draft, caret, selection or permissions changed, close the form and capture again. Cancel leaves the draft unchanged.

By default the complete proposal must target this document. The explicit open-draft option supports complete review of other captured same-language drafts. Closed targets and file operations remain unsupported. It does not execute returned commands, and it does not apply only the edit part of an edit-and-command action. Titles and explanations are shown literally, without executing markup.

This is an explicit temporary query. It synchronizes the captured draft only. By default the diagnostic context is empty. Select Include fresh diagnostics for fixes to wait for a matching publication and request actions in the same server session. Diagnostics from earlier connections are never replayed. Large messages or slow server startup may exceed the connection limits. Saved executable and argument settings are ordinary local preferences; keep credentials out of them.

If a choice cannot be previewed, read the reported reason and choose a supported action or use a tool that handles the entire operation. Do not treat a partial edit as a completed refactor.

Inspect source diagnostics

Include diagnostics for fixes

  1. In Actions, select Include fresh diagnostics for fixes before requesting actions.
  2. The server must publish diagnostics after the captured document opens. Framework checks the source and sends relevant original diagnostic objects back through that same connection.
  3. Review and approve the returned edit as usual. Changing the option retires older results and approval.

This option shares the request timeout and fails if no matching publication arrives. It does not silently fall back to range-only actions. An empty publication is allowed; it does not establish a successful project build.
