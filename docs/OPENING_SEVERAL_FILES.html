Open several files in Studio

Open related source files together without replacing the tabs you already have.

  1. Choose File → Open. The native chooser is titled Open Files.
  2. Select up to 32 local text files. On Windows, hold Ctrl to select separate files or Shift to select a range, then confirm the chooser.
  3. Studio opens the selection one file at a time. Each successful source becomes an editor tab. An already-open source keeps its existing draft.
  4. Read the completion notification. If some files failed, the File opening results window lists every selected path and outcome. Successfully opened tabs remain available.

Handle a failed item

A missing file, permission failure, unsupported binary file or file beyond the editor's size limit may be rejected. Correct the problem and retry that item. The other files do not need to be reopened. A selection larger than 32 is rejected before any item from that selection opens.

Choosing a source file does not automatically add it to a project, change build settings or grant workspace trust. Use Open Workspace Folder to select a project. Existing Save, Save As and Save All commands remain separate from opening.

Open files from your desktop

  1. In your desktop file manager, select up to 32 local source files.
  2. Drag them over Studio's editor or welcome area and release them.
  3. Studio queues them through the same document service as Open File. Review the completion message and any per-file failure report.

Dropping a file that is already open selects its existing document, preserving unsaved text. A mixed local selection can open valid files while reporting missing or unsupported files. Remote links and oversized selections are rejected before queuing; use a local copy or a smaller selection. Dropping a folder does not select it as a workspace: use Open Workspace Folder for that operation.

Stop pending opens or review results

Choose File → Cancel Opening Files to stop queued items. Files already opened remain available. Cancellation becomes available between individual reads; it cannot interrupt a synchronous file read. Choose File → Opening Results after completion to review every result again. The same actions are available in the command palette. They are disabled when no matching queue or completed report exists.

Host integrations

The native host's umi_studio_gtk_workbench_open_files method queues the same workflow. An OK return means the request was queued; inspect umi_studio_gtk_workbench_open_files_snapshot until its running flag clears, then inspect individual results. Call on the GTK owning thread and continue processing its main context.

umi_studio_gtk_workbench_cancel_open_files cancels pending items while retaining successful tabs. Closing the host stops pending opens. A synchronous individual file read can still take time; opening several files does not make the document provider a background-thread service.
