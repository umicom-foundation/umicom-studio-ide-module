Find and replace literal text

The editor toolbar searches the complete current draft, including unsaved text. Its search settings apply to Find, Previous, Replace, Replace All, Review Open Documents and Review Complete Set.

  1. Open a source document and type the text to find into the Find field. This is literal text: characters such as *, . and [ match themselves.
  2. Choose a case mode. Smart case is the default: a query with an uppercase ASCII letter matches case; a lowercase query ignores ASCII case. Match case always compares exact bytes. Ignore ASCII case treats uppercase and lowercase ASCII letters alike even when your query contains capitals.
  3. Select Whole word to avoid matching part of a larger identifier. For example, foo matches foo but not foobar, foo_ or foo2. Letters, digits, underscore and non-ASCII bytes are treated as part of words.
  4. Select Find or Previous. Search wraps at the document boundary. Navigation works in read-only drafts and does not save or add a text Undo action.
  5. For a single change, fill the replacement field and select Replace. A selected match is replaced only if it meets the current case and whole-word rules in the full document. Otherwise Studio replaces the next valid match. An empty replacement removes the match. Undo restores the previous draft.
  6. For multiple changes, choose a review workflow below. Inspect the complete proposed text and its captured search policy before applying. Save remains a separate action.
WorkflowWhat you review and apply
Replace AllAll non-overlapping matches in the active draft, followed by one explicit Apply decision.
Review Open DocumentsA captured list of open drafts, reviewed one at a time. Apply or Skip each draft; Stop keeps any changes you already accepted.
Review Complete SetEvery captured writable draft. Review each changed comparison, approve the whole set, then apply the complete draft transaction. Undo remains per document.

Search choices live with the current editor toolbar. They are not saved as user preferences.

Understand the captured policy

A review copies the current case and whole-word settings. Changing toolbar settings afterwards affects future searches and reviews, not the question already open. Cancel or close the old review and start another when you want different matching. A changed source draft requires a fresh review before applying.

Limits and troubleshooting

This is not regular-expression matching or language-aware symbol renaming. Unicode text is matched exactly rather than using a full Unicode case-folding algorithm; non-ASCII punctuation also participates in the conservative word-boundary rule. If a match is missing, check case mode and Whole word, then inspect the exact text.

Read-only drafts reject editing. Complete-set replacement requires every captured draft to be writable; sequential review can skip read-only documents. Review workflows retain their existing source-size and document-count limits. No workflow silently saves a file.
