Find editor tools without a crowded toolbar

The editor keeps Undo, Redo, Save, text search and common file controls on its toolbar. Source assistance and location tools are grouped into searchable menus beside Save. The groups contain the original actions, with the same document checks and review steps.

  1. Open a document and choose Code tools. This group contains completion, formatting, source information, symbols, parameter help, rename, code actions, diagnostics, definitions, references, type definitions, implementations, syntax selection, callers, callees and snippets.
  2. Type part of an action name into Filter actions. Search also understands descriptive keywords: for example, call hierarchy finds Callers and Callees, while quick fix finds code actions.
  3. Select the desired action. Filtering itself never opens a provider, edits source or chooses an action for you. Each tool keeps its normal form and confirmation behavior.
  4. Open Navigate and view for matching brackets, enclosing selections, manual folding and session bookmarks. Filtering this group does not change the Code tools filter.
  5. Clear the filter to show the entire group. Each group remembers its current filter while the editor toolbar remains alive. Scroll inside a group when its actions exceed the available height.

Search uses a case-insensitive substring of action names and keywords. Canonically equivalent Unicode text matches too. It searches these descriptions only; it does not search your source files or send the query to a service. Disabled actions stay disabled. A message appears when no actions match.

The toolbar still scrolls horizontally when the workbench is narrow. Existing automation identities remain attached to the original buttons, even though those buttons now live inside groups. The general command-search workflow remains available for registered commands.
