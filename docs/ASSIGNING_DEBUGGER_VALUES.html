Change a paused program's variable

Use this workflow when you want to try a different runtime value while debugging. It changes the running program; it does not rewrite your source code or save a permanent setting.

  1. Configure a native debugger, start a debug session and pause at the place you want to inspect.
  2. Open the Debug workspace. Choose the stopped thread and frame, then use Inspect scope or Inspect children to find a variable.
  3. Expand Change value in paused program beneath that variable. Enter the new value using the program's language. For example, enter 7 for an integer; string syntax depends on the adapter and language.
  4. Review the variable name, its captured value and your replacement. Select Apply this value to the paused program, then choose Set value. Changing your draft clears that confirmation.
  5. Read the notification. After an attempted assignment, old variable rows are removed because their references may no longer be valid.
  6. Choose Inspect scope again to read current values. This is a separate request; an assignment confirmation alone is not a readback.

If the action is unavailable

The adapter must advertise variable assignment and the session must be paused with a current captured row. Scopes themselves cannot be assigned. Several children with the same name remain inspectable, but the assignment button is disabled because the adapter cannot identify that row unambiguously. Hover over Set value to see why it is unavailable.

If the assignment is not confirmed

A timeout or malformed reply can happen after the program has already changed. Do not keep pressing the old button. Inspect the current scope, or pause again if execution resumed, and decide what to do from fresh evidence. Studio never retries the assignment automatically.

If a preflight check refused the action, no request was sent and the draft remains available. The replacement must fit within 1023 UTF-8 bytes. An empty draft is a real empty replacement only when you explicitly confirm it. Adapters may execute target code while assigning a value, so inspect the stopped location before changing it.

This workflow edits named variables through the adapter's setVariable capability. It does not provide arbitrary expression assignment, automatic undo or assignment support for an adapter that lacks that capability.
