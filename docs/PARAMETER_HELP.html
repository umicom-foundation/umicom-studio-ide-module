Read function parameter help

Use the editor's Parameters… action to read function overloads and their arguments. Framework supplies the shared reader, native connection and inspection form; Studio supplies the current document, project folder and local settings namespace.

  1. Open a source file and put the caret inside a function call.
  2. Choose Parameters…. Studio captures the current draft and caret, including unsaved text. Read-only documents are supported.
  3. Choose an installed language server using its absolute executable path, ordinary arguments and absolute project folder. Use Load saved server if you previously saved settings for this language. Opening the form and loading preferences do not start a server.
  4. Choose Request parameter help. This explicitly sends the captured draft to the selected program, which can inspect the project folder.
  5. Select an overload to see its signature and parameter descriptions. The active parameter is marked. An exact server-supplied span is highlighted; ambiguous string labels remain unhighlighted.
  6. Close the form when finished. The source is unchanged. Reopen the form after moving the caret or editing the document.

If help is unavailable

Check that the executable is a language server for the file's language, that it supports signature help and that the project is configured for that server. A missing result can simply mean there is no callable symbol at the captured location. Studio does not install or configure the server automatically.

The form allows five seconds for native initialization and reply reads, then performs separate cleanup. Its 65536-byte native message limit includes escaped source text and protocol fields. Large drafts or slow project startup may exceed those limits. Changing server settings clears previous results; results from closed forms cannot be published into a later form.

Descriptions are literal text, including Markdown or HTML supplied by a server. There are no edit-approval controls in this workflow. Saved executable and argument settings are ordinary local preferences and should not contain credentials. This action is an explicit temporary query; automatic parameter popups and persistent indexing are separate capabilities.
