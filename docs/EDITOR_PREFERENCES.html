Change indentation for this Studio session

  1. Open the editor and expand Code tools.
  2. Choose Editor preferences. You can search the menu for “tab width” or “indentation”.
  3. Choose a whole tab width from 1 to 16 and whether Tab should insert spaces.
  4. Choose Apply to session. Existing source text is not rewritten. With no selection, Tab inserts indentation up to the next stop; with a selection, Tab indents the selected lines.
  5. Use Shift+Tab to remove one indentation level. Undo applies to text edits, not to changing preferences.

Apply changes to the current session first. Then choose Save applied preferences to store that pair in Studio's user-local configuration folder. A save does not include later changes or an unapplied form draft. Its completion message shows the saved values and location.

Normal Studio startup loads saved preferences in the background. If you change the session before loading completes, the newer session values remain. Missing files leave the defaults in place; malformed files are reported without being rewritten. Close without applying to discard the form draft.

If the form cannot apply

If preferences changed elsewhere, close and reopen the form before applying again. Studio retains the newer values rather than overwriting them. If a document operation is busy, finish that operation and retry. An incomplete or out-of-range width is rejected.

Tab stops use logical Unicode scalar columns; wide characters and combined graphemes can occupy different visual widths. This is indentation support, not a complete source formatter.

Enter and existing indentation

In a source editor, Enter repeats the current line’s leading spaces and tabs. Shift+Enter inserts a plain line ending. Both replace any selected text, preserve the current LF or CRLF convention, and use the shared Undo history. They do not guess indentation from braces or change your file on disk; use Save separately.
