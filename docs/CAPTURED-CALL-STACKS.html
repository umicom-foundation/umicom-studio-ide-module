Review a captured call stack

Use this report when discussing a debugger stop or saving the observed function chain in your own notes. Framework owns the copied records and native review; Studio supplies the current project and debugger workspace.

  1. Open a project and enable its trusted build tools.
  2. Open Run and Debug. Configure an installed debugger, start or attach it, and pause at the location you want to inspect.
  3. Select the stopped thread. Choose Review captured call stack.
  4. Source paths start omitted. Choose filenames or full paths when useful, then review the displayed text.
  5. Choose Copy reviewed text. Paste it into your chosen destination yourself.

The report contains only retained frames, in the current workspace order. It does not evaluate expressions, fetch more frames or read source files. It may be incomplete and does not update when execution continues. Capture again for a newer observation.

A missing or running thread cannot be captured. If the report has zero frames, inspect that thread through the debugger first. Invalid text from an adapter is rejected for formatting. The review closes with its Studio window. Buttons retained from a closed or hidden workbench cannot start a review.

Omitting source paths is not a complete privacy filter: names can contain private data. The report excludes variable values, watches and launch arguments. Review all text before sharing it.
