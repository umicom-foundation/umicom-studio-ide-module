Native languages and the C boundary

Use this guide alongside the Bits2Banking course Native languages working together through C. The shared implementation remains C; the other languages demonstrate deliberate interfaces, not replacements for Framework services.

Open a lesson and its example

  1. Open Guided Learning in Studio. This bundled guide is available as Native languages and the C boundary after the application package is rebuilt.
  2. For the longer course, choose the Bits2Banking checkout as the library root and learning-packs/native-language-interoperability.json as its manifest path. Load the library and select its course guide.
  3. Keep a separate practice workspace. Read the source before running its commands. Opening a lesson never starts its compiler.
  4. Begin with the common C archive and installed SDK setup. Then select one language client and its matching target.

Read the shared declaration first

int BtbActivityNext(int current);

A nonnegative result is the next count; -1 means refusal. The function retains no pointer and allocates no heap memory. The original implementation and build recipes are in Bits2Banking. The following complete client sources are reading examples; use the course archive and SDK commands to link them.

C model

Source: labs/native/framework-activity/activity.c

/*-----------------------------------------------------------------------------
 * Bits2Banking
 * File: labs/native/framework-activity/activity.c
 *
 * PURPOSE:
 *   Keep checked exercise-count logic independent of its console and GTK presentations.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT
 *---------------------------------------------------------------------------*/

#include "activity.h"
UmiStatus BtbActivityAdvance(unsigned current, unsigned *next)
{
    if (next == 0 || current > 1000U) return UMI_STATUS_INVALID_ARGUMENT;
    if (current == 1000U) return UMI_STATUS_CAPACITY_EXCEEDED;
    /* Validate before addition and publication. No caller observes a partial
     * update, and the fixed upper bound proves the addition cannot overflow. */
    *next = current + 1U;
    return UMI_STATUS_OK;
}

C bridge

Source: labs/native/activity-adapters/bridge.c

/*-----------------------------------------------------------------------------
 * Umicom Bits2Banking
 * File: labs/native/activity-adapters/bridge.c
 *
 * PURPOSE:
 *   Translate platform integers into the existing activity contract.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT
 *---------------------------------------------------------------------------*/

#include "bridge.h"
#include "../framework-activity/activity.h"
int BtbActivityNext(int current)
{
    unsigned next = 0U;
    /* Check the signed boundary before converting. The shared activity model
     * remains responsible for its upper limit and success/failure decision. */
    if (current < 0) return -1;
    if (BtbActivityAdvance((unsigned)current, &next) != UMI_STATUS_OK) return -1;
    return (int)next; /* The activity contract bounds successful values to 1000. */
}

Rust boundary

Source: labs/languages/rust-activity/activity.rs

/*-----------------------------------------------------------------------------
 * Umicom Bits2Banking
 * File: labs/languages/rust-activity/activity.rs
 *
 * PURPOSE:
 *   Wrap the existing C activity bridge in a checked Rust result.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT
 *---------------------------------------------------------------------------*/


use std::ffi::c_int;

unsafe extern "C" {
    fn BtbActivityNext(current: c_int) -> c_int;
}

#[derive(Debug, PartialEq, Eq)]
pub enum ActivityError {
    Refused,
}

/// The C bridge owns the counting rule; this function translates its result.
pub fn advance(current: c_int) -> Result<c_int, ActivityError> {
    // SAFETY: the linked declaration matches bridge.h: one C int in and out.
    // There are no pointers, retained buffers, callbacks or shared mutable state.
    // The bridge accepts every int and reports invalid values with -1.
    let result = unsafe { BtbActivityNext(current) };
    if result < 0 { Err(ActivityError::Refused) } else { Ok(result) }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn ordinary_and_final_success() {
        assert_eq!(advance(0), Ok(1));
        assert_eq!(advance(41), Ok(42));
        assert_eq!(advance(999), Ok(1000));
    }

    #[test]
    fn refuses_capacity_and_invalid_values() {
        for value in [-1, c_int::MIN, 1000, 1001, c_int::MAX] {
            assert_eq!(advance(value), Err(ActivityError::Refused));
        }
    }

    #[test]
    fn each_call_is_independent() {
        assert_eq!(advance(41), Ok(42));
        assert_eq!(advance(1000), Err(ActivityError::Refused));
        assert_eq!(advance(41), Ok(42));
    }
}

Zig boundary

Source: labs/languages/zig-activity/activity.zig

// -----------------------------------------------------------------------------
// Umicom Bits2Banking
// File: labs/languages/zig-activity/activity.zig
//
// PURPOSE:
//   Translate the existing C activity bridge result into a Zig error union.
//
// AUTHOR AND ORGANISATION:
// Sammy Hegab
// Umicom Foundation
//
// LICENCE:
// MIT
// -----------------------------------------------------------------------------
const std = @import("std");
extern fn BtbActivityNext(current: c_int) c_int;

pub const ActivityError = error{Refused};

pub fn advance(current: c_int) ActivityError!c_int {
    // The C bridge is the only implementation of input and count rules.
    // No pointer crosses this boundary and no state is retained by the bridge.
    const next = BtbActivityNext(current);
    if (next < 0) return error.Refused;
    return next;
}

test "ordinary values and final permitted transition" {
    try std.testing.expectEqual(@as(c_int, 1), try advance(0));
    try std.testing.expectEqual(@as(c_int, 42), try advance(41));
    try std.testing.expectEqual(@as(c_int, 1000), try advance(999));
}

test "capacity and invalid signed values are refused" {
    const invalid = [_]c_int{ -1, std.math.minInt(c_int), 1000, 1001, std.math.maxInt(c_int) };
    for (invalid) |value| try std.testing.expectError(error.Refused, advance(value));
}

test "a refusal does not change a later call" {
    try std.testing.expectEqual(@as(c_int, 42), try advance(41));
    try std.testing.expectError(error.Refused, advance(1000));
    try std.testing.expectEqual(@as(c_int, 42), try advance(41));
}

Zig client

Source: labs/languages/zig-activity/main.zig

// -----------------------------------------------------------------------------
// Umicom Bits2Banking
// File: labs/languages/zig-activity/main.zig
//
// PURPOSE:
//   Present checked C activity results from a small Zig command-line client.
//
// AUTHOR AND ORGANISATION:
// Sammy Hegab
// Umicom Foundation
//
// LICENCE:
// MIT
// -----------------------------------------------------------------------------
const std = @import("std");
const activity = @import("activity.zig");

pub fn main() void {
    const values = [_]c_int{ 0, 41, 999, 1000 };
    for (values) |current| {
        const next = activity.advance(current) catch {
            std.debug.print("{d} -> refused\n", .{current});
            continue;
        };
        std.debug.print("{d} -> {d}\n", .{ current, next });
    }
}

Fortran client

Source: labs/languages/fortran-activity/main.f90

! Umicom Bits2Banking
! File: labs/languages/fortran-activity/main.f90
! 
! PURPOSE:
! Call the existing checked C activity bridge using interoperable integer values.
! 
! AUTHOR AND ORGANISATION:
! Sammy Hegab
! Umicom Foundation
! 
! LICENCE:
! MIT
! 
program activity_client
  use iso_c_binding, only: c_int
  implicit none
  interface
    function activity_next(current) bind(C, name="BtbActivityNext") result(next)
      import c_int
      integer(c_int), value :: current
      integer(c_int) :: next
    end function activity_next
  end interface
  integer(c_int), parameter :: inputs(5) = [-1_c_int, 0_c_int, 41_c_int, 999_c_int, 1000_c_int]
  integer(c_int), parameter :: expected(5) = [-1_c_int, 1_c_int, 42_c_int, 1000_c_int, -1_c_int]
  integer :: i
  integer(c_int) :: next
  do i = 1, size(inputs)
    next = activity_next(inputs(i))
    ! VALUE passes a C int rather than the address of the Fortran variable.
    if (next /= expected(i)) error stop 1
    print '(I0,A,I0)', inputs(i), ' -> ', next
  end do
end program activity_client

/*-----------------------------------------------------------------------------
 * Umicom Bits2Banking
 * File: labs/languages/d-activity/main.d
 *
 * PURPOSE:
 *   Use the existing C activity contract from D BetterC without a managed runtime.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT
 *---------------------------------------------------------------------------*/

import core.stdc.stdio : printf;
extern(C) int BtbActivityNext(int current) nothrow @nogc;
extern(C) int main() nothrow @nogc
{
    immutable int[5] inputs = [-1, 0, 41, 999, 1000];
    immutable int[5] expected = [-1, 1, 42, 1000, -1];
    foreach (index, current; inputs) {
        const int next = BtbActivityNext(current);
        // Explicit checks remain active even if the compiler disables assertions.
        if (next != expected[index]) return 1;
        printf("%d -> %d\n", current, next);
    }
    return 0;
}

package main
import "core:c"
import "core:fmt"
import "core:os"
// Supply -collection:activity=<archive directory>. This is an explicit build
// input, not a search of another application or the current working directory.
foreign import activity "activity:libbtb-activity-adapters.a"
foreign activity {
    BtbActivityNext :: proc "c" (current: c.int) -> c.int ---
}
main :: proc() {
    inputs := [5]c.int{-1, 0, 41, 999, 1000}
    expected := [5]c.int{-1, 1, 42, 1000, -1}
    for current, index in inputs {
        next := BtbActivityNext(current)
        if next != expected[index] { os.exit(1) }
        fmt.printf("%d -> %d\n", current, next)
    }
}

 * Umicom Bits2Banking
 * File: labs/native/assembly-activity/forward.S
 *
 * PURPOSE:
 *   Demonstrate an x86-64 C ABI tail call without duplicating the checked C implementation.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT

#if !defined(__x86_64__)
#error This lesson requires an x86-64 target; use the C client on other architectures.
#endif
#if !defined(_WIN32) && !defined(__linux__)
#error This lesson covers Windows x64 and Linux x86-64, not every object format.
#endif
.text
.globl BtbAssemblyActivityNext
#ifndef _WIN32
.type BtbAssemblyActivityNext, @function
#endif
BtbAssemblyActivityNext:
    /* Both functions use the same ABI. Preserve the argument register (ECX on
     * Windows, EDI on Linux), stack and caller return address. The C function
     * writes EAX and returns to the original caller. No additional frame exists. */
    jmp BtbActivityNext
#ifndef _WIN32
.size BtbAssemblyActivityNext, .-BtbAssemblyActivityNext
.section .note.GNU-stack,"",@progbits
#endif

C assembly test driver

Source: labs/native/assembly-activity/main.c

/*-----------------------------------------------------------------------------
 * Umicom Bits2Banking
 * File: labs/native/assembly-activity/main.c
 *
 * PURPOSE:
 *   Compare an assembly forwarding call with the shared C activity contract at boundary values.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT
 *---------------------------------------------------------------------------*/

#include "../activity-adapters/bridge.h"
#include <limits.h>
#include <stdio.h>
extern int BtbAssemblyActivityNext(int current);
int main(void)
{
    const int inputs[] = {INT_MIN, -1, 0, 41, 999, 1000, INT_MAX};
    const int expected[] = {-1, -1, 1, 42, 1000, -1, -1};
    for (size_t i = 0; i < sizeof inputs / sizeof inputs[0]; ++i) {
        int next = BtbAssemblyActivityNext(inputs[i]);
        if (next != expected[i] || next != BtbActivityNext(inputs[i])) return 1;
        printf("%d -> %d\n", inputs[i], next);
    }
    return 0;
}

Verify and troubleshoot

Follow the per-language commands in the course. Keep missing compilers, failed links and executed test failures separate. A recognised extension is not a working language server. A generated C file is not evidence that memory ownership is correct. Match ABI, target, library identity and runtime before changing the shared rule.

Use the existing Learning C, C++, Rust, Zig and D courses for fundamentals, and the new Fortran, Odin and Nim introductions for their first programs. Links to external prerequisites may need another admitted pack or a browser. Source availability is not an executed native reader or installed-SDK qualification.

D, FreeBASIC and Umicom C projects

New Project now includes D Console Application and FreeBASIC Console Application. Install a complete LDC or FreeBASIC distribution, together with CMake and Ninja, before choosing these recipes. D needs its matching druntime, Phobos and supported linker/host SDK. FreeBASIC needs its matching runtime, headers and linker. Studio's tool inspection reports file discovery; it does not install or validate every dependency.

  1. Open a fresh terminal with the chosen compiler's bin directory on PATH. Confirm Get-Command ldc2 or Get-Command fbc and run its version command.
  2. Start Studio from that terminal, choose the recipe and a new empty project folder, then review the generated source and CMake files.
  3. Apply Project Settings after reviewing the code and build scripts. Choose Configure, Build, Test and Run. Expected console output is Result: 42.
  4. Read the first error in Output. A missing compiler stops configuration; a missing linker or runtime can still fail later. Follow the generated README for the equivalent terminal commands.
cmake --preset windows-ucrt64-debug
cmake --build --preset windows-ucrt64-debug --parallel 2
ctest --preset windows-ucrt64-debug --output-on-failure --no-tests=error

Run each command separately and stop on errors. On Linux use linux-debug. The generated native program is in the build directory's bin folder. D's unit-test blocks and the exact console output are checked; FreeBASIC includes an internal check and the same output assertion. These starter projects do not yet link the complete Framework SDK.

The Umicom C preview uses the preview preset. Its Run profile invokes the configured CMake preview target instead of guessing a native executable. Ensure umicom-c is installed and discoverable before configuring. For VM inspection use umicom-c debug src/main.uc --max-steps 256 from a terminal. This is separate from the native debugger and supports the current bounded language, not arbitrary C23 or embedded Java/BASIC.

Pascal console projects

Install Free Pascal with the corresponding runtime units and linker. Check Get-Command fpc and fpc -iV from the terminal that starts Studio. Choose Pascal Console Application in New Project. Review its source and CMake files before granting trust, then Configure, Build, Test and Run. The test checks that the program exits successfully and prints Result: 42.

The generated README lists the exact terminal steps and the Runtime staging command. Use the same generated project from Studio and Umicom Command. Debugger startup and Pascal symbol inspection depend on the installed native debugger and its compatibility with the compiler.

Twenty-language tool coverage

Framework language records and optional tool inspection cover C, C++, assembly, D, FreeBASIC, Rust, Zig, Fortran, Go, Ada, Pascal, Java, Kotlin, C#, Swift, Python, JavaScript, TypeScript, Lua and Julia, plus Umicom C. This is a practical selection rather than a speed ranking. C/C++, assembly, Rust, Zig, Python, D and FreeBASIC have relevant starter recipes; several other languages still need a user-supplied build/run/test profile. A language record alone does not enable an end-to-end debugger.

FreeBASIC .bas/.bi, Ada .adb/.ads and Julia .jl now participate in shared filename detection, selection, filters and line-comment editing. Their line-comment prefixes are ', -- and # respectively. On Windows tool inspection recognises Kotlin's kotlinc.bat and TypeScript's tsc.cmd; a reviewed task must still execute script launchers through a suitable command interpreter.

Native debugger compatibility depends on compiler, debug format and target architecture. JVM, .NET and interpreted-language debug sessions require their own adapters. Hosted tools run on the underlying Windows/Linux system; they do not establish that the same programs run bare-metal on Umicom Kernel. An installed Studio package must be rebuilt from matching Framework sources before these changes appear.
